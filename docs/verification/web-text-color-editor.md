## 颜色输入法交互修复（2026-10-22）

基于 `77d08749e1cd3dc89e7620e9bba476036640522f`，修复先选色再输入后无法保存、同一流程中已着色文字无法再次改色的问题。离线实际编辑器使用 `BACKEND_URL=http://127.0.0.1:9`，无业务后端；Chromium 1280×850 的事件记录复现了 `ni → 你` 变成 `ni你你`、缺少 `compositionend`，以及颜色按钮禁用。

根因是显式输入色插件在每次正文变化后设置 `storedMarks`，触发 ProseMirror 在组词途中清除组合状态并重设 DOM 选区；浏览器的结束事件丢失，提交保护仍认为输入法未结束。修复让组词期间的颜色只作用于本次输入范围，保留默认输入事务的选区和组合元数据，结束后再恢复后续输入格式；下一轮组词和卸载取消待执行的格式恢复。命令层也拒绝未完成组词时改色。未删除或放宽 Markdown bridge、保存或离开编辑器的输入法保护。

回归覆盖实际 ProseMirror 组合状态、结束后的正文同步、连续组词、光标移动、卸载、默认色及粗体。新增测试在修复前复现“组合提前结束”和“组词中改色被接受”；修复后 5 项通过。原有命令、取色器和删除/输入同步测试继续通过。浏览器新增旅程覆盖普通输入、Chromium CDP 组合输入、未完成组词阻止发布、取消候选、已着色选区再次改色、自定义取消、默认色、撤销/重做、服务端保存正文及刷新后的阅读结果。
