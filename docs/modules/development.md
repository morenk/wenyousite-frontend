# Web 日常开发

## 启动与反馈

Web 只在 VPS 的独立任务 Worktree 修改和运行。普通 `pnpm dev` 直接启动 Next.js，默认监听 `127.0.0.1:3101`；选择空闲端口时可传入 `--port`。agent 启动或复用自己的进程与 SSH 转发，不接管其他任务会话。`BACKEND_URL` 必须显式提供，也可以保存在未提交的 `.env.local` 中；不需要 Backend 快照或会话描述。旧 `WENYOU_PREVIEW_*` / `NEXT_PUBLIC_WENYOU_PREVIEW_*` 配置即使为空也会拒绝启动；先停止本任务旧会话并移除这些配置，再用普通入口启动，不能让旧会话静默切换模式。

```bash
pnpm install --frozen-lockfile
BACKEND_URL=http://127.0.0.1:3000 pnpm dev --port 3101
```

本机使用普通 SSH 转发并保持进程运行：

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 3101:127.0.0.1:3101 wenyou-dev-vps
```

访问 `http://127.0.0.1:3101`。已有端口被占用时先识别所属进程，选择本任务空闲端口，并同步修改转发目标；以实际启动日志和监听地址为准，不停止他人服务。浏览器始终访问同域 `/api/v1`，Next.js 将其代理到显式配置的 `BACKEND_URL`。

连续反馈使用 Fast Refresh，无需逐轮 production build、部署、提交或推送。记录任务、Worktree、源码 SHA/摘要、进程、端口、后端地址和视口；同一批次保留页面状态。停止时只终止本任务进程和 SSH 转发，不操作后端服务或数据。依赖和 Next 配置变化后按需重启本任务 dev 进程。

## 数据与自动化边界

示例 `http://127.0.0.1:3000` 是现有真实数据后端。`next dev`、loopback 和 SSH 转发都不提供数据隔离：手动登录、发帖、上传或自动签到会作用于所连接的后端。启动前明确实际目标，凭据仅由正常登录流程处理，不复制真实会话，不提交 `.env.local`。

agent 对真实数据环境的自动化验收仍只允许匿名只读烟雾；不能自动登录或执行可能产生业务写入的交互。需要写入的自动化测试继续使用独立 E2E runner，由它核验资源、代理目标、登记和清理；缺少隔离身份时停止，不回退到现网。没有可写测试环境时可以用组件测试或本机合成 fixture 检查呈现，但不能冒充真实数据或端到端验收。

媒体上传继续使用后端签发的 URL 和现有生产 CSP，下载继续校验本站固定发布地址；更换后端不会自动拓宽媒体源或下载信任范围。开发进程不修改正式服务，构建和部署继续遵守仓库门禁。

## 检查与交付

样式反馈先查看实际画面并运行相关组件测试，覆盖受影响的明暗主题和窄视口；本项目仍为 PC Web。记录未覆盖状态，没有实际画面时标记待视觉验收。

反馈收敛后执行 `pnpm check`；认证、权限或核心旅程按风险执行隔离 `pnpm check:full`。写入 E2E 和线上匿名只读烟雾分别报告，细则见 [E2E 接入说明](../rich-text-real-api-acceptance.md)。提交、PR、负责人合并和部署授权仍是独立步骤。
