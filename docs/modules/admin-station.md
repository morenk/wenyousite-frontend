# PC 站务台、举报与申诉

## 产品边界

站务台只提供 PC Web 界面，不进入公共导航并设置 `noindex`。管理员身份来自一个已注册的温油账号，但后台使用独立 HttpOnly Cookie 会话：密码和管理员验证码建立会话，高风险操作再次邮件确认；普通用户 access token 不能进入管理 API。公开前台中的管理员权力入口是另一条受限通道：服务端直接以普通 Bearer 登录态实时校验管理员角色，不要求站务会话。

移动端不提供后台界面。用户举报、决定查询和申诉使用平台无关的普通 Bearer JSON API；PC 站务会话只用于管理 API。

## 路由

| 路由 | 说明 |
|------|------|
| `/station` | 独立站务登录 |
| `/station/invite?token=` | 已登录温油账号接受管理员邀请 |
| `/station/dashboard` | 用户、待办、活跃趋势和服务健康总览 |
| `/station/cases` | 举报聚合案件、证据和处置 |
| `/station/content` | 按前台链接或内容编号直接隐藏、恢复内容，并列出当前仍被隐藏的内容 |
| `/station/appeals` | 申诉复核与决定推翻 |
| `/station/users` | 用户检索、处罚和解除 |
| `/station/announcements` | 站内通知受众预览、排期与取消 |
| `/station/taxonomy` | 分类和标签注册表：编辑显示信息、排序和启停 |
| `/station/accounts` | 管理员邀请、撤销和超级管理员移交，仅超级管理员可见 |
| `/station/operations` | 注册/写入紧急开关和维护公告 |
| `/station/audit` | 不可变决定轨迹 |
| `/report` | 普通用户举报表单 |
| `/me/moderation` | 当前用户收到的决定与申诉入口 |

所有站务页面固定最小桌面宽度，复用中央 foundation token 和字体。左侧一级导航收口为站务总览、内容治理、运营配置、安全与权限四个功能域；后三组通过 Base UI Collapsible 展开二级页面，当前路由所在分组自动展开，超级管理员入口继续按服务端会话角色控制。案件页采用固定导航、案件队列、证据/处置工作区；列表能力使用 TanStack Table，表单使用 React Hook Form 和 Zod，服务端状态使用 TanStack Query。

## 列表筛选与分页

- 案件、申诉、用户、当前隐藏内容、审计和通知活动使用后端不透明游标；每页 20 条，Web 只保存访问过的上一页游标，不解析或改写游标。改变任一筛选条件会回到第一页。
- 案件可组合状态、目标类型和举报原因；申诉可组合状态、目标类型和原处置；用户可组合关键词、角色和处罚状态；当前隐藏内容可按内容类型筛选；审计可组合动作、目标类型、目标 ID 与北京时间日期区间；通知活动可组合关键词、发送状态和跳转目标。
- 管理员账号、待接受邀请、主题分类和平台标签是单次返回的小型配置登记册，使用 TanStack Table 的客户端分页与业务筛选，避免为低基数配置另建平行分页协议。
- 所有列表使用带固定列名和独立操作列的传统数据表格，状态、主体、时间和数量不藏进卡片；筛选区只使用高对比中性色，品牌色仅标记当前选择，业务状态再使用对应状态色。
- 所有列表始终显示分页器、当前页条数、明确的上一页/下一页禁用状态，以及可一次清除组合条件的筛选带；搜索框不作为唯一筛选能力。
- 面向站务人员的字段名、状态和操作说明使用自然中文；稳定标识、目标编号等确需保留的技术值必须配中文字段名。
- 列表筛选使用 `nuqs` 保存为类型化 URL 查询参数：刷新或分享链接会恢复同一筛选，非法枚举会安全回落。管理员账号、邀请、分类和标签的客户端页码也写入 URL；后端不透明游标仍只保存在当前 Web 会话的访问栈中，不暴露或改写跨端游标。
- 总览的举报处理趋势使用 Recharts 双柱图，提供数量坐标、悬浮明细和无障碍图表层；没有时间序列数据时显示明确空状态。

## 客户端边界

- 所有 API 经过共享 `apiClient`；`src/api/types.ts` 只由固定 OpenAPI 生成。
- 管理 CSRF token 只保存在内存中，由 `/admin/auth/session` 返回；仅对管理写请求附加 `X-CSRF-Token`。
- 普通用户 access token 和管理员 Cookie 会话互不替代。接受邀请后清除普通 Web 本地会话，再跳转站务登录。
- 普通前台登录态为 `ADMIN / SUPER_ADMIN` 时，公开主题帖、楼层/回复、动态和动态评论显示“站务隐藏”入口；提交直接调用 `/moderation/content/:type/:id/hide`，使用当前普通 Bearer 登录态，不核验独立站务 Cookie、CSRF 或邮件 step-up。服务端从数据库实时校验角色，普通用户即使自行构造请求也会被拒绝。
- `/station/content` 接受裸内容编号，也可从主题帖 `?post=`、楼中楼、动态 `?comment=&reply=` 链接自动识别精确目标。页面下方列表只展示当前仍满足 `removalSource=ADMIN` 的记录，可直接填写复核理由恢复；父级仍不可见的行会禁用恢复并解释原因。隐藏成功后先移除必然返回 404 的目标详情缓存，再异步刷新公开列表和审计，成功按钮不等待 404 重试；恢复只用于管理员隐藏的内容，作者主动删除不会被改写。
- 站务列表、详情、决定和写入通过 `src/api/hooks/use-admin.ts` 统一缓存及失效，不在组件内直接 `fetch`。
- 分类的 `slug` 是主题帖外键和跨端接口使用的稳定标识，创建后不可修改；名称、描述、颜色、排序和启停状态由站务台编辑。分类写入成功后同时失效站务列表与公开分类缓存，不需要等待五分钟缓存过期。
- 举报表单显式携带 `targetType/targetId`；私聊举报由后端再次确认当前用户是接收者。

## 验证

`pnpm check` 覆盖 lint、TypeScript、生成契约、架构/设计约束、单元测试与覆盖率、文档事实检查和生产构建。后台接口变更必须先生成后端 OpenAPI，再同步前端契约；不手改生成类型。
