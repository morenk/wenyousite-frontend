# 动态模块

## 目标与范围

动态区是独立于主题帖的短内容交流区。第一版支持纯文字或最多 9 张图片、发现/关注双流、动态搜索、点赞、收藏、加油、两层楼中楼评论、用户主页动态和动态收藏。标题、正文与评论文字均以 React 文本节点渲染，不解析 Markdown 或 HTML；每条评论可附一张普通图片或一个收藏表情包。

## 页面与交互

| 路由 | 行为 |
|------|------|
| `/moments` | 与发现页共用 42rem 固定中栏和等宽侧轨；中栏使用 2/1 列虚拟化瀑布流并保留右侧快捷信息；发现按服务端固定时间截面的热度游标，关注按时间倒序；页面标题区不重复放发布按钮 |
| `/moments/[id]` | 可直接访问的动态详情页，使用不超过 36rem 的紧凑正文列 |
| `@modal/(.)moments/[id]` | 从瀑布流进入时使用 36rem 宽、可回退的路由拦截弹层，刷新仍落到详情页 |
| `/search?q=…` | 默认动态 Tab，仅搜索动态标题和正文，至少 2 个字符 |
| `/bookmarks` | “主题帖 / 动态”分类收藏 |
| `/users/[id]` | 用户公开动态瀑布流 |

卡片主体不使用常驻边框或紫色填充。图片封面优先使用 480px `_feed.webp` 派生图，并保留横图、方图的原始比例；过长竖图最多收束到 3:4，文字封面保持 3:4。两列由真实卡片高度独立排布，不要求左右卡片顶边或底边互相对齐。无图片时由服务端持久化的 `textCoverTheme` 和标题生成“温油便笺”文字封面，确保分页、刷新和跨端颜色稳定。瀑布流卡片只保留标题、作者与点赞，收藏、评论和加油集中在详情页。

详情轮播的图片舞台以封面图比例确定，并将最大高度限制为 `min(51vh, 29rem)`；切换不同比例的图片时只在固定舞台内使用 `object-contain` 适配，不推动下方标题和正文。多图只显示当前一张，通过左右箭头循环轮播并显示张数，不再压成网格；点击当前图片进入大图查看。拦截弹层由外壳裁切完整圆角，细滚动条在内层滚动容器中留出上下边距，不再破坏右侧圆角。

已登录用户统一从左栏的文楷“发布”按钮选择“发布主题帖 / 发布动态”；发布动态直接打开全局动态发布器，动态页面头部不再重复提供同一入口。

## 发布流程

- 标题必填 2～40 字；正文可空，最多 1000 字。
- 图片最多 9 张，动态不接受 GIF。发布前在浏览器将长边限制为 1920px、以 0.82 质量转为 WebP，只上传压缩文件，不向对象存储发送原图；封面必须是本动态图片之一，默认第一张。
- 无图时不允许指定图片封面，文字封面主题由 `clientRequestId` 稳定决定。
- 发布使用 UUID `clientRequestId` 幂等；编辑携带 `version` 乐观锁；作者可编辑或软删除。
- 发布器草稿保存在浏览器 IndexedDB，包括标题、正文、图片预览和所选封面；成功后清理草稿。
- 发布器使用固定视口高度的双栏工作台；标题栏与底部操作栏固定在右栏，标题、正文和最多 9 张图片只在中间内容区滚动，多图换行不会把发布按钮挤出屏幕。
- 图片直传可通过右上角关闭、Esc、遮罩或“取消上传”中止；取消后保留草稿且不会继续提交动态。对象存储直传等待超过 120 秒时终止，并提示检查网络后重试。

## 评论与可见性

主评论默认按时间倒序分页，每条按当前阅读顺序预载 3 条回复；楼中楼默认按时间正序分页。评论标题旁使用单个按钮在“最新在前 / 最早在前”之间切换，不提供按回复者筛选；服务端排序和 cursor 使用相同条件，不在浏览器里重排单页。回复任意楼中楼时，服务端将新评论归并到所属主评论，并保留实际 `replyToComment`，视觉层级始终只有两层。

评论文字最长 500 字且只按普通文本渲染。正文、图片、表情包至少提供一项；图片与表情包共用一个媒体位，一条评论最多选择一个。普通评论图片沿用动态图片前端压缩规则：长边不超过 1920px、转为 0.82 质量 WebP 后再上传，不向对象存储发送原文件；GIF 应通过收藏表情包发送。选择新的图片或表情包会替换原选择，上传中可用预览右上角移除按钮取消。

评论输入框使用与正文列对齐的底部悬浮坞，默认收成一行，点击发表或回复后展开，并按浮层真实高度在评论列表末尾留白。回复页面深处的评论时用 `preventScroll` 聚焦输入框，不把阅读位置跳回评论区顶部；弹层详情中的输入坞保持在弹层遮罩上方。

双向任一拉黑都会过滤动态、评论和搜索结果，并禁止继续回复。评论作者、动态作者和管理员可以软删除评论；删除采用条件更新，累计评论数只扣减一次。动态详情通知携带结构化 `momentId` / `momentCommentId`，目标被删除时前端显示不可跳转状态。

## API 与缓存

| Method | Path | 用途 |
|--------|------|------|
| GET | `/moments?feed=DISCOVER\|FOLLOWING` | 动态流；关注流要求登录 |
| POST / PATCH / DELETE | `/moments`、`/moments/:id` | 幂等发布、乐观锁编辑、软删除 |
| POST / DELETE | `/moments/:id/like` | 幂等点赞 / 取消 |
| POST / DELETE | `/moments/:id/bookmark` | 幂等收藏 / 取消 |
| GET / POST | `/moments/:id/comments` | 主评论列表 / 发布评论 |
| GET | `/moments/:id/comment-authors` | 当前查看者可见的评论作者筛选候选 |
| GET | `/moments/:id/comments/:commentId/replies` | 楼中楼分页 |
| DELETE | `/moments/:id/comments/:commentId` | 软删除评论 |
| GET | `/users/:id/moments` | 用户动态 |
| GET | `/moments/bookmarks` | 当前用户动态收藏 |
| GET | `/search/moments` | 标题与正文搜索 |
| POST | `/moments/:id/tips` | 给动态作者加油 |

所有查询通过 `src/api/hooks/use-moments.ts` 和 `useSearchMoments` 管理，query key 包含流类型、查看者与筛选条件。点赞在 mutation 发出前同步乐观修补详情、信息流、用户动态、收藏及搜索缓存，服务端失败时只回滚该动态；请求期间不改变按钮颜色或透明度。瀑布流使用 TanStack Virtual measured lanes，只挂载可视区域附近卡片；`ResizeObserver` 回写真实卡片高度，较短封面会自然形成左右错落，底部 sentinel 触发游标翻页。

## 验收标准

- [x] 图文和纯文字动态均可发布，并能选择图片封面
- [x] 无图动态生成稳定的文字封面
- [x] 发现/关注流、搜索、用户动态和动态收藏可游标翻页
- [x] 瀑布流只渲染可视区域附近卡片，长列表滚动不随总量线性变卡
- [x] 点赞、收藏、加油、评论和删除具备明确登录/权限处理
- [x] 楼中楼只有两层，回复目标语义不丢失
- [x] 所有动态正文和评论均为普通文本
- [x] 详情同时支持拦截弹层和直接路由
