# 动态模块

## 目标与范围

动态区是独立于主题帖的短内容交流区，支持纯文字或最多 9 张图片、发现/关注双流、动态搜索、点赞、收藏、加油、两层楼中楼评论、用户主页动态和动态收藏。标题保持普通 React 文本；正文与评论不解析通用 Markdown 或 HTML，只按[站内传送门 v1](./internal-references.md)激活命名或裸主题坐标，其他语法保持字面文本。每条评论可附一张普通图片或一个收藏表情包。

平台管理员可在动态详情和每条未删除评论/回复旁打开“站务隐藏”。提交使用当前普通 Bearer 登录态，服务端实时校验管理员角色，不要求独立站务 Cookie、CSRF 或邮件 step-up；成功后动态发现流、个人动态、详情和评论查询同步失效。动态隐藏后返回动态区；评论或回复正文不再公开，维持回复树结构所需时只保留“该评论已删除”占位。恢复统一在 `/station/content` 通过原链接或内容编号执行。

## 页面与交互

| 路由 | 行为 |
|------|------|
| `/moments` | 与发现页共用 42rem 固定中栏和等宽侧轨；中栏使用 2/1 列虚拟化瀑布流并保留右侧快捷信息；发现按服务端固定时间截面的热度游标，关注按时间倒序；紧凑排头只保留标题和流切换，不重复放发布入口或解释性副标题 |
| `/moments/[id]` | 直接替换 42rem `feed` 中栏内容的动态详情页；返回栏、标题卡片、图片画廊与正文区使用同一组中栏内边线，左右侧轨的位置与宽度不变 |
| `/search?q=…` | 默认动态 Tab，仅搜索动态标题和正文，至少 2 个字符 |
| `/bookmarks` | “主题帖 / 动态”分类收藏 |
| `/users/[id]` | 用户资料“概览”Tab 只在创作汇总中展示动态总数，不重复挂载动态卡片 |
| `/users/[id]/moments` | 用户资料“动态”Tab，展示完整公开动态瀑布流并按游标继续加载；与其他资料 Tab 共用持久 Layout，切换时资料头部不卸载 |

卡片主体不使用常驻边框或紫色填充。图片封面优先使用 480px `_feed.webp` 派生图，并保留横图、方图的原始比例；过长竖图最多收束到 3:4，文字封面保持 3:4。两列由真实卡片高度独立排布，不要求左右卡片顶边或底边互相对齐。无图片时由服务端持久化的 `textCoverTheme` 和标题生成语义色文字封面；ROSE、LILAC、MINT、AMBER 分别复用设计系统已有的 primary、secondary、success、warning 色对，不增加第二套品牌标签或写死色值，同时确保分页、刷新和跨端主题稳定。瀑布流卡片只保留标题、作者与点赞，收藏、评论和加油集中在详情页。

从瀑布流点进动态时，详情作为普通页面替换中栏，不再使用遮罩或弹出卡片。详情顶部提供“返回动态”：从主动态流进入时通过同标签页历史恢复原来的发现/关注状态和滚动位置；直接访问详情或标记失效时回到 `/moments` 发现流。用于识别返回来源的一次性 `sessionStorage` 上下文只保存动态 ID、Feed 类型、滚动坐标、固定来源和时间，不保存列表内容或用户数据。

详情首屏先展示标题卡片：作者、发布时间、编辑/删除入口、完整标题以及点赞/收藏/加油汇总合并在同一区块，标题位于图片之前且不截断，不再显示“动态”眉题；即使图片舞台达到最大尺寸，进入页面也先完整呈现标题与核心互动。图片轮播紧接标题卡片，左右边线与标题卡片、正文区和返回栏一致；舞台最大高度限制为 `min(72vh, 42rem)`，比例仍由封面图确定，切换不同比例的图片时只在固定舞台内使用 `object-contain` 适配，不推动其他区块。多图使用 Embla 轨道，只显示当前一张并支持鼠标/触控拖拽、左右箭头、张数和缩略图快速定位；点击当前图片进入原图灯箱，可用键盘切换与缩放。

已登录用户统一从左栏的文楷“发布”按钮选择“发布主题帖 / 发布动态”；发布动态按需加载并打开全局动态发布器，未打开时不进入初始客户端包，动态页面头部不再重复提供同一入口。发现/关注、搜索分类和收藏分类均复用共享 `Tabs` 的方向键与 ARIA 语义。

## 发布流程

- 标题必填 2～40 字；正文可空，最多 1000 字。
- 正文工具栏可在当前选择处插入命名站内传送门；单独粘贴主题、楼层、回复或私密邀请地址时也会立即显示传送门，选区文字优先作为名称。标记本身计入 1000 字限制。
- 动态或评论包含私密邀请传送门时，首次提交或邀请内容变化后必须确认公开分享风险；同一内容请求失败后的重试不重复确认。
- 图片最多 9 张，动态不接受 GIF。发布前在浏览器将长边限制为 1920px、以 0.82 质量转为 WebP，只上传压缩文件，不向对象存储发送原图；封面必须是本动态图片之一，默认第一张。
- 无图时不允许指定图片封面，文字封面主题由 `clientRequestId` 稳定决定。
- 发布使用 UUID `clientRequestId` 幂等；编辑携带 `version` 乐观锁；作者可编辑或软删除。
- 发布器草稿保存在浏览器 IndexedDB，包括标题、正文、图片预览和所选封面；成功后清理草稿。
- 发布器使用共享 `Dialog` 的焦点圈定、Esc、遮罩关闭与页面滚动锁定，并呈现固定视口高度的双栏工作台；标题栏与底部操作栏固定在右栏，标题、正文和最多 9 张图片只在中间内容区滚动，多图换行不会把发布按钮挤出屏幕。
- 图片直传可通过右上角关闭、Esc、遮罩或“取消上传”中止；取消后保留草稿且不会继续提交动态。对象存储直传等待超过 120 秒时终止，并提示检查网络后重试。
- 发布器固定底栏逐张显示“第 n/N 张”的准备、真实字节上传进度和媒体处理状态；按钮同步显示当前百分比，不能再用单一旋转图标覆盖几十秒直传等待。

## 评论与可见性

主评论默认按时间倒序分页，每条按当前阅读顺序预载 3 条回复；楼中楼默认按时间正序分页。详情正文与评论列表连续阅读，不额外显示“楼中楼 / 评论”标题；排序按钮在“最新在前 / 最早在前”之间切换，不提供按回复者筛选；服务端排序和 cursor 使用相同条件，不在浏览器里重排单页。回复任意楼中楼时，服务端将新评论归并到所属主评论，并保留实际 `replyToComment`，视觉层级始终只有两层。

评论文字最长 500 字，只额外激活站内传送门，其他 Markdown/外链保持字面文本；评论工具栏可插入命名传送门，单独粘贴合法站内地址也会所见即所得显示，标记计入长度。正文、图片、表情包至少提供一项；图片与表情包共用一个媒体位，一条评论最多选择一个。普通评论图片沿用动态图片前端压缩规则：长边不超过 1920px、转为 0.82 质量 WebP 后再上传，不向对象存储发送原文件；GIF 应通过收藏表情包发送。表情展示与帖子、私聊共用 128px 最大宽高，静态表情优先请求缩略图，动图请求服务端规范化资产。选择新的图片或表情包会替换原选择；压缩阶段显示明确文案，直传阶段显示真实字节与百分比，预览移除或进度区取消会中止发送。

评论输入框使用与正文列对齐的底部悬浮坞，默认收成一行，点击发表或回复后展开，并按浮层真实高度在评论列表末尾留白。回复页面深处的评论时用 `preventScroll` 聚焦输入框，不把阅读位置跳回评论区顶部。

展开楼中楼后始终提供收起入口；回复总数超过 10 条时，收起入口改为停靠在当前楼中楼区域顶部的悬浮按钮，阅读上百条回复时无需先滚到末尾。收起后视口返回所属主评论，避免大段内容移除后失去阅读位置。

双向任一拉黑都会过滤动态、评论和搜索结果，并禁止继续回复。评论作者、动态作者和管理员可以软删除评论；删除采用条件更新，累计评论数只扣减一次。动态详情通知携带结构化 `momentId` / `momentCommentId`，目标被删除时前端显示不可跳转状态。

动态评论通知链接使用 `comment` 标识所属主评论，并在目标为楼中楼时额外携带 `reply`。详情页以 `reply ?? comment` 调用评论上下文接口；目标不在当前分页时直接注入主评论和楼中楼、去重后自动展开、滚动并保持定位高亮，不遍历后续分页。定位中显示进度；目标已删除、因拉黑不可见或不存在时保留动态和普通评论并显示行内提示，临时失败可重试定位。

## API 与缓存

| Method | Path | 用途 |
|--------|------|------|
| GET | `/moments?feed=DISCOVER\|FOLLOWING` | 动态流；关注流要求登录 |
| POST / PATCH / DELETE | `/moments`、`/moments/:id` | 幂等发布、乐观锁编辑、软删除 |
| POST / DELETE | `/moments/:id/like` | 幂等点赞 / 取消 |
| POST / DELETE | `/moments/:id/bookmark` | 幂等收藏 / 取消；收藏可指定私有收藏夹 |
| PATCH | `/moments/:id/bookmark` | 移动到其他私有收藏夹 |
| GET / POST | `/moments/:id/comments` | 主评论列表 / 发布评论 |
| GET | `/moments/:id/comment-authors` | 当前查看者可见的评论作者筛选候选 |
| GET | `/moments/:id/comments/:commentId/replies` | 楼中楼分页 |
| GET | `/moments/:id/comments/:commentId/context` | 按主评论或楼中楼 ID 获取精确定位上下文 |
| DELETE | `/moments/:id/comments/:commentId` | 软删除评论 |
| GET | `/users/:id/moments` | 用户动态 |
| GET | `/moments/bookmarks?folderId=` | 当前用户动态收藏，可按收藏夹筛选 |
| GET | `/users/:id/moment-bookmarks` | 用户公开动态收藏，服从 showBookmarks |
| GET | `/search/moments` | 标题与正文搜索 |
| POST | `/moments/:id/tips` | 给动态作者加油 |

所有查询通过 `src/api/hooks/use-moments.ts` 和 `useSearchMoments` 管理；发现/关注、搜索、用户动态和动态收藏消费同一动态卡片基础字段，本人收藏额外带 `bookmarkFolderId`，公开用户收藏不带任何私有归类字段。query key 包含流类型、查看者、收藏夹、用户动态页容量与筛选条件。首次收藏先在共享弹窗选择收藏夹，成功后同步修补动态状态并失效收藏列表和分类计数；取消仍保持直接开关语义。点赞在 mutation 发出前同步乐观修补详情、信息流、用户动态、收藏及搜索缓存，服务端失败时只回滚该动态；请求期间不改变按钮颜色或透明度。主题帖与动态的已点赞状态统一使用 Foundation 鲜粉实心心形，动态详情的已收藏状态使用金色实心书签；选中容器保持透明，计数保持正文色，未选中均为中性描边，hover、focus 与 pressed 只在图标命中区显示瞬时状态层。请求中用 loading 图标阻止重复提交但保留提交前的选中视觉、稳定动作名称和 `aria-pressed`。瀑布流使用 TanStack Virtual measured lanes，只挂载可视区域附近卡片；`ResizeObserver` 回写真实卡片高度，较短封面会自然形成左右错落。虚拟项进入距列表末尾约两行的预取区时触发游标翻页，不依赖未挂载的 DOM sentinel。

## 前端库采用边界

- 保留 TanStack Query 与 TanStack Virtual：缓存、乐观更新、游标分页和 measured-lanes 虚拟瀑布流已经覆盖动态区核心难点，不替换为非虚拟化瀑布流库。
- 图片排序使用当前左右移动按钮。
- 动态发布草稿使用现有原生 IndexedDB 单表单存储。
- 详情图片画廊采用 [Embla Carousel React](https://www.embla-carousel.com/docs/v8/get-started/react) 实现拖拽、吸附、箭头与缩略图同步；原图查看采用 [Yet Another React Lightbox](https://yet-another-react-lightbox.com/) 的 Zoom 插件，灯箱仅在打开时动态加载。两者只负责交互机制，颜色、圆角和阴影继续由项目语义 Token 控制。
- 当前图片上限 10MB，上传沿用预签名、XHR 真实进度、确认和处理轮询链路。

## 验收标准

- 图文和纯文字动态均可发布，并能选择图片封面
- 无图动态生成稳定的文字封面
- 发现/关注流、搜索、用户动态和动态收藏可游标翻页
- 瀑布流只渲染可视区域附近卡片，长列表滚动不随总量线性变卡
- 点赞、收藏、加油、评论和删除具备明确登录/权限处理
- 点赞与收藏分别呈现鲜粉、金色选中态；计数不随图标染色，pending 保留提交前视觉
- 楼中楼只有两层，回复目标语义不丢失
- 动态评论通知可定位到具体主评论或楼中楼；超过 10 条的已展开楼中楼始终可从悬浮按钮收起
- 动态正文和评论只激活站内传送门，其他 Markdown 与外链均保持普通文本；单独粘贴合法站内地址时立即显示可编辑传送门
- 详情直接替换固定 42rem 中栏，标题与核心互动在图片之前，标题卡片、图片、正文和返回栏边线一致且左右侧轨不位移
- 多图画廊支持拖拽、箭头、缩略图定位和原图缩放，并保留完整键盘可达性
- 从动态流返回时恢复原列表状态和滚动位置，直接访问时回到发现流
