# 站内传送门

Web 消费 [`contracts/internal-reference-v1-fixtures.json`](../../contracts/internal-reference-v1-fixtures.json)，并由 `pnpm contract:sync` 与后端机器事实源同步。站内主题帖、子贴、主楼层、楼中楼讨论、具体回复和 16 位 token 的私密帖邀请 `/join/{token}` 统一显示为正文内联“传送门”，不因引用来源或目标类型生成不同 label、卡片或摘要。输入接受 `wenyou.site`、`www.wenyou.site` 与相对坐标并规范化为相对地址；邀请坐标不接受查询参数或片段。

传送门呈现由 Foundation `experiences.elements.inline.internalReference` 拥有：阅读态和编辑态使用同源 `content.internal-reference` 门图标与轻量柔粉胶囊，长名称可换行且不截断；编辑态阻止点击导航。普通链接、用户提及、行内代码、骰子、引用和分隔线不得复用传送门外观。

显式 `\[设定 A\]\(/threads/…\)` 只显示“设定 A”；名称中的反斜线和方括号按标准转义解码及往返，裸站内地址显示“传送门”。裸地址必须具备完整左右边界，不能从更长 URL、路径或标识符中截取片段。内联元素复用 primary / brand 语义色和小型开门图标，保持正文行高，ARIA 名称为 `站内传送门：{名称}`，使用 Next 同标签导航。站外链接继续在新标签页打开。目标是否存在或可见只由点击后的既有 404 / 权限状态处理，渲染阶段不请求目标元数据。

帖子正文由 Markdown v3 工具栏白名单处理，Milkdown 的普通链接入口即可构造传送门。动态正文和评论仍是字符串：只激活 `[名称](合法站内坐标)` 与裸站内坐标，其他 Markdown 和外链原样显示；发布、编辑和回复均使用只增强传送门的轻量所见即所得编辑器。动态发布、编辑和评论工具栏提供“传送门”按钮，名称与链接通过 RHF/Zod 校验，写回规范化相对 Markdown 语法；当前选择文本预填为名称，写回后恢复文本光标。

所有 Web 正文编辑入口都在剪贴板纯文本整体只有一个合法站内地址时立即插入可见传送门。有选区时沿用选区文字为名称，没有选区时使用“传送门”；混合文本和站外链接继续走既有粘贴链路。编辑态传送门点击只用于放置光标、选择或修改链接，不打开目标；阅读态才执行同标签导航。既有显式语法与裸地址在重新编辑时也直接显示为传送门，未修改时保持原字符串写法。

主题详情以 URL 为目录状态事实源。非默认子贴使用 `?subthread={id}`，默认子贴删除该参数；切换使用 shallow history replace，不发起 RSC 请求，左右游标和菜单选项走同一回调。`post` 精确目标优先于 `subthread`，二者并存时保留 `post` 并清理 `subthread`；无效子贴回落到默认并清理 URL。页面导航可保留 `order` 等界面状态，目录菜单复制或编辑器插入的分享地址只包含 `post` / `subthread` 等内容坐标；复制默认子贴时得到主题根地址。

列表或摘要降级时，显式传送门只保留名称，裸传送门变为“传送门”。私聊正文也只额外激活传送门和安全 `http/https` 链接；整段粘贴合法坐标时写入规范化语法，气泡导航而复制保留原始正文。会话列表对新旧 `contentPreview` 均防御脱敏：普通传送门显示名称，邀请或残留 `/join/{token}` 显示“邀请传送门”，不暴露 token。

私密邀请 token 是访问凭据，把传送门发布到公开内容仍等同于公开分享邀请。公开主题、子贴正文、楼层、回复、动态和评论首次提交邀请或邀请内容变化时必须确认；同一内容失败重试不重复确认，私聊与私密主题不弹公开分享确认。解析与编辑过程不预取私密帖元数据。历史内容不迁移，旧字符串和普通链接继续兼容。
