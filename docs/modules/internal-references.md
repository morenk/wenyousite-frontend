# 站内传送门

Web 消费 [`contracts/internal-reference-v1-fixtures.json`](../../contracts/internal-reference-v1-fixtures.json)。站内主题帖、子贴、主楼层、楼中楼讨论和具体回复统一显示为正文内联“传送门”，不因引用来源或目标类型生成不同 label、卡片或摘要。

显式 `\[设定 A\]\(/threads/…\)` 只显示“设定 A”；裸站内地址显示“传送门”。内联元素复用 primary / brand 语义色和小型开门图标，保持正文行高，ARIA 名称为 `站内传送门：{名称}`，使用 Next 同标签导航。站外链接继续在新标签页打开。目标是否存在或可见只由点击后的既有 404 / 权限状态处理，渲染阶段不请求目标元数据。

帖子正文仍由 Markdown v2 处理，Milkdown 的普通链接入口即可构造传送门。动态正文和评论仍是字符串：只激活 `[名称](合法站内主题坐标)` 与裸站内主题坐标，其他 Markdown 和外链原样显示。动态发布、编辑和评论工具栏提供“传送门”按钮，名称与链接通过 RHF/Zod 校验，写回规范化相对 Markdown 语法；当前选择文本预填为名称，写回后恢复文本光标。

主题详情以 URL 为目录状态事实源。非默认子贴使用 `?subthread={id}`，默认子贴删除该参数；切换使用 `router.replace`，左右游标和菜单选项走同一回调。`post` 精确目标优先于 `subthread`，无效子贴回落到默认并清理 URL。目录菜单提供复制当前子贴链接，复制默认子贴时得到主题根地址。

列表或摘要降级时，显式传送门只保留名称，裸传送门变为“传送门”。历史内容不迁移，旧字符串和普通链接继续兼容。
