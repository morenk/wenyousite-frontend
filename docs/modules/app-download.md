# APP 下载

## 入口与呈现

外观弹层在省流量设置下方提供独立的“下载 APP”导航行，关闭弹层后进入公开 `/download`。游客、登录用户、登录页与窄视口复用同一入口，不要求登录。页面使用 `PageShell` 内容宽度、共享按钮和 Foundation 图标及明暗 Token；不引入移动版社区布局。

页面显示同一 Android 制品的版本名、构建号与安装包大小（B / KiB / MiB），并提供安装说明。桌面二维码由本地 `qrcode.react` 生成 SVG，编码 `https://wenyou.site/download`，旁边保留可读链接；二维码不包含固定 APK、桶或签名 URL。无推荐、撤回、暂停和不可用状态仍可查看页面与二维码。

## 信息状态与重试

`useAppDownload` 经 `apiClient` 读取匿名 `GET /api/v1/app-downloads/android`，DTO 直接消费生成类型。`available` 展示制品；`no_release`、`withdrawn`、`paused`、`unavailable` 分别显示无推荐、撤回、暂停和暂不可用，禁止下载。缺少字段、不一致状态或不可信下载地址作为加载失败处理，不推断无发布。

信息请求失败显示原地重试。已有信息刷新失败可以保留版本展示，但暂停下载；刷新期间同样不可下载。信息和文件请求均不自动重试，也不在窗口重新聚焦或网络恢复时重试。`retryAfterSeconds` 与可读取的 `Retry-After` 限制手动重试；等待结束只恢复控件，不自动发出请求。

## 下载触发与制品绑定

浏览页面、框架预取、悬停、聚焦、二维码生成和手动刷新信息均不请求文件端点。菜单关闭 Next 预取，页面不持有可预取的文件链接。

用户激活下载按钮后，才通过 `apiClient.HEAD` 预检固定构建文件。状态码、大小、摘要、包名、版本和构建号必须与点击时的制品一致；无 Range、无重定向、无自动重试。只有信息仍有效、没有并行刷新或推荐变化、页面仍存在时，才将同源固定路径交给隐藏的受限下载框架（仅允许下载及同源访问，不允许脚本或顶层导航），由浏览器保存文件，不使用 fetch/blob 缓存完整 APK。双击不会产生并行预检；离开页面取消预检。

文件 429 显示稍后重试并尊重等待时间；502、503、未知构建或元数据不匹配显示暂不可用。信息或文件请求的空正文错误仍按 HTTP 状态与 Retry-After 恢复，不将其误判为无发布。结构化暂停可来自运维暂停或额度不足，遵守建议等待时间，不推测恢复时刻。HEAD 成功不保证后续 GET 正文额度充足。恢复动作只重新获取信息，不自动继续文件下载。版本变化取消旧预检交接，要求重新核对，不把正在进行的固定构建下载改指新版。

浏览器接管后页面只显示交接提示，并暂停同一按钮，避免预检很快完成时的连续点击重复传输；如需再次下载，先手动重新获取信息。原生 GET 后续失败或完成无法回传 HTTP 状态或 Retry-After；页面保留交接说明及“重新获取下载信息”入口，不显示无法观察的倒计时或宣称下载完成、已校验、已安装。GET 429（JSON 或空正文）、503、502 留在下载页，恢复动作仍只读信息，不自动重传；实际下载结果由浏览器下载列表确认。HEAD 核验只用于交接前身份一致性，不替代 Android 安装校验。

## 契约与发布边界

契约来源及同步见 [API 契约](api-contract.md#公开-app-下载)，跨端语义与稳定验收 ID 来源于 [Foundation 已提交说明](https://github.com/morenk/wenyousite-foundation/blob/100ddf0db555d5a4c0bff733f19fa9b9e6f7f6ac/docs/app-downloads.md)。继续使用正式包 `v7.2.1`，本功能不新增 Token 或 Foundation 包版本。

兼容网关与发布工具先行，完成预热后才启用消费端；已安装 APP 验收完成后，APK 公共读清理由独立审批处理。Web 不回退存储桶，不预热、不配置预算、不修改云权限；本仓不执行合并、部署或正式发包。回滚边界见 [弃用登记](../deprecation-register.md#公开-app-下载)。

## 验证

本任务的隔离画面、会话绑定与覆盖边界见 [视觉候选记录](../app-download-validation.md)。

- `app-download.test.ts` 核验地址、制品身份、等待时间和大小格式。
- `use-app-download.test.tsx` 与下载页组件测试覆盖 `browse-without-file-request`、信息状态、`info-refresh-failure`、`info-target-race`、显式点击、浏览器交接、限流和文件失败。样本由生成 DTO 约束，不对应线上制品。
- `e2e/app-download.spec.ts` 继承隔离 fixture，覆盖匿名键盘入口、明暗与窄屏、实际二维码截图像素解码、无障碍扫描和浏览器保存隔离样本。该样本验证 HTTP 交接，不是正式 APK 安装验证。
- 浏览器用例必须由隔离 runner 运行。实时视觉候选使用 Backend 已提交的消费者描述启动 `pnpm dev:preview`，记录 session、源码摘要、视口和截图时间；组件断言不替代画面验收。
- 合成下载预览由消费者描述的 `sample: downloads` 标记，页面标识显示“合成样本”。此环境每次读取信息前核验实际 Web 代理身份，仅接受本轮隔离 Backend 返回的绝对地址，再转为 Web 同源路径；不能仅凭 loopback 放宽来源，不接触线上制品或正式安装。
