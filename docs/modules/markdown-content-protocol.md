# Markdown v5 正文内容协议

Web 与 Flutter 共用数据库中的 Markdown 字符串，不修改既有字段或数据表。

## 协议事实源

- 协议标识为 `wenyousite-markdown`，当前版本为 `5`。
- Web 仓库中的 `contracts/markdown-v4-fixtures.json`、`contracts/markdown-v4-nodes-fixtures.json`、`contracts/markdown-editor-roundtrip-v7-fixtures.json`、`contracts/markdown-v5-image-alignment-fixtures.json` 与 `contracts/editor-clipboard-v2-fixtures.json` 是后端同名黄金语料的同步副本，依次固定规范化/允许与拒绝结果、扩展节点身份、编辑器往返、图片块对齐，以及跨端复制入口、结构恢复、原子身份和可见文本回退。
- 后端是写入校验的最终权威；Web 对外部粘贴和阅读执行安全降级；历史正文与草稿的编辑入口先检查无损能力，不以降级文字覆盖原文。Flutter 必须把五份语言无关 JSON 语料纳入单元测试。
- 规则变更必须先提交黄金语料；仅测试覆盖和兼容规范化使用 fixture revision，不擅自提升正文协议版本，禁止单独修改某一端正则。
- `contracts/markdown-block-boundary-v1-fixtures.json` 补充顶层块边界、保护区、原始错误位置、编辑与复制以及空格布局回归；它是 Markdown v5 的兼容解析修正，不引入新存储格式。revision 2 同步自 Backend 提交 `a91cbb8b605223c596af299be22c5547f69e25b9`，SHA-256 为 `822509411fbf3379847a04ec64a4a32ddb1bb8fb96aecbf38b395b049134fda9`。
- [Web 实际保存验收语料](../verification/markdown-block-boundaries-web-output.json) 记录该 revision 的 173 个允许用例、4 个真实编辑操作和 1 个空白布局用例经 Milkdown 保存的实际结果，供后端独立验证消费者输出；所有内容均来自合成用例。
- 独立 Worktree 可先用 Git 从明确提交导出该 fixture，再运行 `pnpm contract:sync --block-boundary-source <文件>`，只同步该文件。完整同步、契约核对和文档事实检查统一支持 shell 环境变量 `WENYOUSITE_BACKEND_ROOT`；默认仍为相邻后端目录，显式指定的来源或契约缺失时检查失败。选择来源前须记录其 Git SHA，不能用路径选择绕过不一致。
- Web 的发布、回复、编辑和草稿入口传递完整规范正文，不做全局 `trim()`；`trim()` 只允许用于空内容判断，首尾空段落及空白必须保留。

## 工具栏能力白名单

主工具栏、“更多”面板及显式键盘命令遵循现有结构化正文能力。无序/有序列表的可见入口已隐藏，仍保留历史列表的阅读、编辑、保存、站内复制和底层命令，不缩减正文协议。允许普通段落、二级/三级标题、左/中/右对齐、粗体、斜体、删除线、行内代码、安全链接与自动链接、图片、引用、普通有序/无序列表、分隔线、提及、骰子、收藏表情，以及独占 `<br />` 协议空段；列表最多嵌套三层。手动键入 `## `、`> `、列表符、强调符、反引号、删除线、对齐协议或分隔线源码都只产生可见文字，不触发 Markdown input rule；标题快捷键也只保留 H2/H3。

安全链接中的合法站内坐标在编辑态显示为传送门。剪贴板纯文本整体只有一个合法站内地址时，编辑器立即创建普通链接 mark：当前选区文字作为名称，无选区时使用“传送门”。这只改变链接的编辑态呈现，持久化仍是标准 Markdown 链接，未扩展 Markdown v5 的结构能力。

表格、任务列表、围栏或缩进代码块、一级及四至六级标题、显式硬换行、任意原始 HTML、未知协议节点和超过三层的列表均不属于正文结构。Web 对外部粘贴和手动输入保留可见字面文本；历史异常正文只读保留原文，不支持的草稿恢复会拒绝替换当前输入；绕过客户端直接提交未转义结构时，后端返回 HTTP 400、错误码 `40009`。第三方 Markdown 解析器支持的额外语法不能扩大产品能力。

一级栏始终保持单行且不横向滚动，各组通过间距组织，不渲染组间竖线，也不让分隔线参与默认／自定义布局的溢出测量。四档密度和每档“更多”内容消费 Foundation 契约，并在呈现层过滤列表入口：容器能放下时平铺全部常用能力，随后依次进入 `with-more`、`without-draft` 与 `compact`。标准与无草稿密度保留行内代码直达，把链接和对齐收进“更多”；最窄核心栏再同时收纳行内代码与链接。“更多”是无分类、无分隔线、无常驻文字的扁平纯图标托盘，宽高随可见工具自然收缩，宽度上限为 320px 与可视区可用宽度的较小值；工具多时换行，对齐按钮作为整体排列，边缘碰撞后仅面板内部滚动。名称只在鼠标悬浮或键盘聚焦时通过 Tooltip 出现；对齐仍是段落能力，在一级栏和更多托盘均只提供居中、右对齐两枚可反选图标；默认居左或混合选区时均不选中，再次点击当前项恢复居左，点击另一项直接切换，混合选区点击后统一所选合格块。底层直接设置命令仍保持幂等；默认居左不写 Markdown 标记。打开托盘时焦点落在托盘本身，不自动聚焦或高亮首项；工具间使用标准 `Tab / Shift+Tab`，不接管方向键或 `Home / End`。

正文样式面板将正文／H2／H3 放在紧凑分段区，按当前选区显示选中态，混合选区与历史层级不误选；字体使用独立轻量入口。默认色、预设色与最近色统一按钮尺寸和选中态，自定义颜色入口独立，无最近记录时不保留空行。打开面板先聚焦面板本身，键盘进入按钮后保留 focus-visible；字体下载、RGB 校验与正文选区恢复沿用原行为。

## 顶层正文对齐

- v4 仅允许顶层非空普通段落和 H2/H3 设为左、居中或右对齐；列表、引用、普通图片、分隔线、协议空段及其他节点不参与。提及、骰子和收藏表情作为行内原子组件继承所在块的对齐。
- 左对齐是默认值且不写存储标记。居中和右对齐分别在目标块紧邻上一行写入 `[wenyousite-align-v1-center]: #` 与 `[wenyousite-align-v1-right]: #`；它们是旧 CommonMark 阅读器会隐藏的 reference definition。
- 标记必须大小写、空格、版本、枚举和邻接关系完全匹配；孤立标记、未知版本、`left` 标记、嵌套目标和不合格目标均按无效对齐处理。文字与普通图片混排仍不能独立对齐；Web 编辑器事务还会主动清除列表/引用转换后遗留的块属性。
- 受保护区外的列 0 精确标记本身建立顶层块边界，前面不要求空行，并终止列表或引用的隐式续行；标记后仍必须紧邻合格目标。校验、阅读准备、编辑回填与摘要共用块分析，错误位置保留原始零基行号；为通用阅读解析器补充的分隔只用于解析，不成为可见空段。
- 围栏、缩进代码、跨行行内代码、转义、原始 HTML 和显式嵌套中的协议字面内容不激活对齐。行内代码保护依据真实解析器消费区间，URL 和链接标题中的反引号不会误保护后续 marker。
- 阅读与编辑 DOM 只使用 `data-wenyou-align="center|right"`，不读取外部 `style`、`align` 或 CSS 推断。Web 始终兼容读取 v4/v5 正文，并只在 `/api/v1/meta.markdownContractVersion >= 4` 时显示块对齐入口、达到 v5 时开放独立普通图片块对齐；当前服务端已声明 v5。

### 普通图片块对齐扩展

`contracts/markdown-v5-image-alignment-fixtures.json` 固定普通图片块的扩展边界。服务端能力声明达到 v5 时，独立占据顶层段落的普通图片可消费同一行前置的对齐标记；无标记保持默认居左，文字与普通图片混排继续拒绝单独移动图片，收藏表情继续作为行内节点继承父段落对齐。Web 阅读器、编辑器图片块、Markdown 编解码和编辑器剪贴板均按服务端版本门控；当前服务端声明 v5，新图片对齐写入入口已开启。

## 字面文本降级

- 外部输入中的不支持结构按源码行转成普通段落，并转义 CommonMark 标点；阅读降级显示原字符。历史正文进入编辑前另做无损能力检查，不把阅读降级结果写回。
- 没有合法本站 clipboard v1/v2 标记的 Markdown、HTML、Word 和其他富文本一律优先采用剪贴板 `text/plain`；缺少纯文本时只提取 HTML 可见文字。即使内容只含白名单格式，也不得交给默认 Markdown/HTML 解析器创建结构。
- 外部拖放使用同一字面文字策略；本地文件拖放和粘贴不插入正文，图片只能经工具栏上传。
- 白名单外外部剪贴板按可见文本插入；历史正文和草稿恢复先检查已知版本与结构能力，不能将有损降级结果写回原正文。编辑器输出端不得运行字面降级器。
- 客户端写出时断言序列化结果仍在白名单内；内部转换失败时保留编辑结构并标为未同步；所有正文保存和关闭入口先同步编码当前文档，失败不提交父表单旧值，也不关闭有新输入的编辑器。后端始终独立校验，不信任客户端。

## 剪贴板 v2

- 阅读态同一篇 `MarkdownContent` 内的浏览器选区，以及楼层/回复菜单的“复制内容”，同时写入受限 `text/html` 站内片段和渲染后的 `text/plain`。跨正文选区不伪造结构；菜单复制整篇正文。编辑器自身的复制/剪切使用相同 v2 envelope，来源记为 `editor`。
- Envelope 写出 `data-wenyou-clipboard="2"` 和 `data-wenyou-clipboard-source="reader|editor"`，并继续读取 v1。标记只是体验信号，不是可信来源：粘贴时重新构造 H2/H3、文字 mark、列表、引用、分隔线及安全链接白名单，丢弃脚本、样式、事件属性和未知节点；未知版本静默使用系统可见文本。
- v2 只为合法顶层 P/H2/H3 保留 `data-wenyou-align="center|right"`，同块内的局部阅读选区会恢复共同块祖先；v1 一律按无对齐结构读取。外部 HTML/CSS/纯文本即使带 `text-align` 也不能创建对齐。
- 阅读态的传送门保留目标与显示名、单人提及保留 `userId` 与 label、`@全体玩家` 保留群体语义、骰子只保留表达式。粘贴骰子总是生成新 `nodeId` 且回到未结算状态；编辑器剪切后的第一次粘贴例外保留原 ID，之后再粘贴按复制处理。
- 阅读态普通图片和收藏表情分别变成 `[图片]` 与 `[表情]`，不会复制 URL 或资产 ID；编辑器内部复制继续保留可编辑媒体节点。所有 `text/plain` 回退只含渲染可见文字，不含 Markdown 定界符、目标 URL 或隐藏身份。
- 单独一个合法本站地址仍是明确例外：外部纯文本粘贴会创建传送门。混合文本、外部拖放或标记丢失时按普通可见文字处理。跨应用、Web↔Android 和跨设备传输仍先验证合法 v1/v2 envelope；保留标记的站内片段恢复允许结构，不能因跨端一概降级。

## Web 编解码边界

- `milkdown-markdown-codec.ts` 是 ProseMirror 文档与持久化 Markdown 之间的唯一写出边界。文档与选区即时更新，普通 `docChanged` 的完整编码在停止输入 120ms 后合并执行，持续输入最长每 500ms 同步一次；长按 Backspace/Delete 仍合并到松键或停止删除 120ms 后。中文组词期间暂停编码和自动保存，完成最终组合事务后恢复；保存、恢复或关闭会提示先完成选词，不把组合输入当成编码失败。`onDocumentChange` 即时通知内容版本变化并使旧草稿队列失效，`onChange` 提供已验证的合并 Markdown 快照（撤销回相同文字也确认版本完成）。成功编码按不可变文档和当前契约版本缓存，纯选区与同一版本的重复 `flush()` 不重新编码。失焦及保存/关闭前的 `flush()` 读取最新文档；React Hook Form 先同步正文再运行表单校验，编码失败不写入旧值。异步确认后复核正文版本，卸载取消待同步任务。不依赖 Milkdown 的防抖 `markdownUpdated` 事件，也不允许骰子、表情、提及、图片等入口各自手动补发正文。正文节点变化不触发工具栏密度重测，工具栏结构和容器尺寸变化仍重新布局。
- Shift+Enter 仍保留为编辑器内 break 节点，但 stringifier 直接写成普通 LF；因此粗体末尾换行稳定输出 `**阿罗**\n下一行`，不会先生成反斜杠硬换行再被整行转义。正文重开时普通 LF 也恢复为可见 break 节点，与完整阅读态一致，不折叠成空格。
- 分隔线只写为与前后正文各隔一个空行的 `正文\n\n---\n\n正文`，并以 `horizontal-rule` 块语义验收；历史 `正文\n---` 按 CommonMark Setext H2 重开，任何编辑后统一写为 `## 正文`，不能按行级正则误判为分隔线。
- 阅读态和编辑器解析态共享同一条 attention 边界兼容：严格 CommonMark 已留在普通 text 节点中的 `* / _ / ~~` 成对定界符，只有内容首尾无空白且至少一侧为 Unicode 标点或符号时才恢复为格式；另兼容历史上恰好一个普通空格误写在定界符内、且后面紧接完整行内代码的粗体、斜体、粗斜体和删除线。恢复前用源码位置确认开闭定界符真实存在且未转义；代码、链接、图片、定义、未闭合/更长定界符和普通词内下划线不变。
- 编辑器写回时把格式节点首尾空白原样移到定界符外，不插入或折叠可见空格；stringifier 仍会把会重新造成歧义的相邻正文字符编码为数字字符引用，保留普通文字的既有定界符规则；斜体直接包含行内代码或与粗体节点相邻时使用下划线定界，避免相邻星号连串歧义。GFM 删除线使用与粗体/斜体相同的相邻字符保护，规范正文重开后保持幂等。
- 段落两端已有空白通过数字字符引用保护，避免 CommonMark 裁剪尾空格；不会增加空白或隐藏字符。
- 卡片、搜索、通知和正文草稿的紧凑摘要按已解析行内节点去除格式，代码内部星号、反引号和实体不再经去格式正则，普通链接仍显示方括号标签、裸链接仍隐藏地址。
- 行内代码允许与粗体、斜体、删除线、链接叠加，工具栏、更多菜单和 Mod-e 添加/取消代码只变更代码 mark；部分选区、撤销和重做保留其他 marks。代码内容作为原子字面串处理，包括星号、反斜杠、实体字面和不同长度的反引号。
- 阅读态普通行内代码使用 500 字重，粗体范围内的行内代码使用 700，包含斜体、链接、删除线中间节点的组合；斜体同时保留。此规则不作用于代码块。
- 历史正文中跨越单个完整行内代码节点的成对 attention 定界符，只有两侧源码位置连续、定界符一致且未转义时恢复外层格式。例如粗体“土地”紧邻由星号包裹的代码“culti”，重开和阅读均保留粗体及斜体代码。实体编码、转义定界符、带空格边界、词内下划线、不匹配定界符与代码内部符号不恢复。
- 骰子使用独立 Markdown AST 扩展节点和对应 stringifier handler，禁止先写成被转义的文本标记再做字符串回填。空图片清理、LF 统一、末尾格式化换行移除和独占 `<br />` 空段规范化属于无损规范化；输出阶段不得修改用户的格式语义。
- 空正文先切换为引用时，Milkdown 内部生成的引用内 `<br />` 占位会在写出边界规范化为合法的 CommonMark 空引用标记；编辑器追加的顶层空段仍沿用 `<br />` 协议。该状态不构成可发布正文，继续输入后正常写为引用正文，不得因内部占位误报原始 HTML。
- 结构块之后连续 Enter 形成的作者空段，必须保留首个 `<br />` 与结构块之间的解析分隔行；随后继续输入时不得将空段及正文吞进列表，也不得改变可见空行数量。
- 正文序列化失败时，编辑区持续显示错误，主题帖保存/发布、楼层/回复提交、子贴保存及正文草稿写入均暂停，避免将父表单中的旧内容误报为已保存。恢复为合法正文（包括撤销回原文）后重新开放；正文草稿恢复仍要求覆盖确认，不因同步失败跳过。
- Milkdown 保留结构块之后可点击的自动输入尾段，空引用沿用原有占位语义。其他自动尾段以私有 ProseMirror 属性记录来源，未使用时不进入 Markdown 或复制片段；属性不输出到 DOM、不从外部 HTML 读取。首次输入转为作者段落并纳入同一撤销历史，输入后清空以及 Enter 生成的空段按真实内容保留，撤销、重做和保存重开保持一致。跨行行内代码按 CommonMark 阅读语义将源码 LF 解释为空格，保存重开稳定，代码中的 marker 始终是字面内容。
- 站内 v1/v2 片段、单一合法站内地址、外部字面粘贴、拖放和文件忽略都在 ProseMirror DOM 事件阶段统一接管，早于默认 clipboard 解析器；只有通过严格重建的站内片段进入 Milkdown 结构解析链。所有工具栏和自定义节点事务最终都由同一个同步桥写出。

## 空段落

- 编辑器将顶层空段落写成独占一行 `<br />`；`<br>`、`<br/>`、`<br >` 仅作为历史兼容输入，写入时规范化为 `<br />`。
- 白名单解析临时用独立分隔块占位，保持协议空段与相邻对齐定义的块边界和行号；普通文字占位会吞并定义而误报无效对齐。该占位不写回正文，空段仍不能携带对齐。
- 客户端渲染时把协议标记转换为安全换行节点，禁止执行任意 HTML。Web 完整阅读在解析前会隔离开头连续协议空段与正文，避免 CommonMark 将未分隔的 `<br />` 误识别为原始 HTML 块后被安全策略整体丢弃。前端摘要、通知和搜索预览会移除空段落标记并折叠连续空白。
- 完整正文阅读态把普通段落内的单个 LF 作为可见软换行保留；紧凑预览不保留该排版。
- 不设空行数量上限，仅受现有 Markdown 总长度限制；首部、中间、尾部空段落均按顺序保留。
- 对旧客户端已经写入的原始连续空行，完整阅读与编辑回填执行只读兼容推断：内部保留一个普通段落边界并把其余空行逐个恢复为空段，首部逐个恢复，尾部仅忽略一个格式化换行；围栏、缩进代码和原始 HTML 字面区域不推断。该兼容不批量改写数据库，正文下次编辑时才自然写回规范标记。

## 发布校验

纯空白、仅空段落或仅一条分隔线不可发布；图片、普通列表、普通文本、裸 HTTP(S) URL、CommonMark 自动链接和带标签链接属于有效内容。空图片/空链接以及不可见零宽字符不构成正文。草稿仍可保存为空。

收藏表情使用标准图片 Markdown `![表情](ASSET_URL "wenyousite-sticker:v1:ASSET_ID")`；Web 把它显示为最大 128px 的不可拆分内联节点，旧客户端按普通图片显示。服务端验证资产仍在作者收藏中并限制每篇 20 个。新普通图片只允许来自作者本地上传并处理完成的站内媒体；编辑历史正文时可原位保留已有外链图片，但不能新增或复制外链图片。

## 完整阅读与预览

楼层、子贴正文、楼中楼预览和独立回复使用同一渲染组件并始终完整展示，不按正文高度或视口高度折叠，也不显示“展开全文 / 收起”控件。连续空段落仍按原始数量参与排版。

搜索结果、主题卡片、用户动态和通知等不渲染完整 Markdown 的界面统一使用纯文本预览转换：HTML/数字实体按阅读语义单遍解码，换行和连续空白折叠为一个空格；骰子协议标记显示为 `[骰子表达式]`，表情显示为 `[表情]`，带标签链接显示为 `[标签]`，裸链接与自动链接显示为 `[链接]`，其他图片显示为 `[图片]`。

### 正文连续空格

完整阅读的普通段落、H2/H3、引用和列表正文保留解析后作者文字中的连续空格；编辑器采用同样的 `break-spaces` 策略。长空格可随容器宽度换行，不推断表格或竖排结构，不改变字体和 Markdown 存储格式。NBSP、全角空格、Emoji 和用于保护行首缩进的 U+2060 按原字符保留；摘要继续折叠空白。

软 LF 仍通过一个安全 `br` 节点换行。阅读转换使用专用内部换行节点，避免通用 Markdown 转 HTML 再次裁掉换行后已经解析的作者空格；数字实体只按原解析器解码一次，代码和转义字面不参与补偿。阅读器移除 Markdown 转 HTML 时生成、且没有源码位置的排版 LF，防止保留空白后把 `br` 后缀或列表块间分隔显示为额外空行；有源码位置的作者文字不参与移除。显式空段继续遵循既有协议。

历史提交 `65446d414d92e550c9ea1703c48c8250aab95eb0` 的格式节点间空格保护仍在基线中：它仅覆盖两个格式节点之间独立的纯空格文本。普通正文的空格折叠来自该保护范围不足，本次保留其回归并扩展正文块的空白样式。

## 稳定性与能力保护

共享操作与能力矩阵来自 Backend `7c6d5bf4c857d3174275a5505c5c008b28f8635a` 的 `rich-text-behavior-v1-fixtures.json`（version 1、revision 2）。行为 fixture、输入 schema 与结果 schema 是合成测试契约，不增加 API、数据库或正文状态字段；newline v1 revision 2、roundtrip v7 和 clipboard v2 继续分别执行。

`useEditorSubmission` 让主帖创建/编辑、子帖管理、楼层/回复共用当前文档的 `flush`。加载中、编码失败和不支持的正文返回失败；空正文与失败明确区分。异步公开邀请确认后复核正文是否变化；网络错误、冲突和不支持响应保留输入，重试由用户发起。未知正文只读显示安全原文，修改旁边的标题也不能覆盖它；未修改的原文允许退出。有未编码新输入时，保存、切换编辑目标和关闭均保留现场。

服务端仅明确识别 3/4/5：3 允许基础内容，4 增加块对齐，5 增加普通图片块对齐。当前 Web 的引用空行读取和提交保护是独立实现能力，不能由版本数字推断旧客户端也支持。未知版本、未知节点、原始 HTML 或缺少写能力时阻止正文写入；阅读降级不作为写回来源。

文字序列化保留字面标记与格式边缘空白；结构块后的自动输入占位沿用统一来源标记，不保存为作者空段。单行外部粘贴替换当前选区，不额外创建段落。空引用、列表及空格式块继续使用各自已有规则。

共享执行器位于 `rich-text-behavior.test.ts`，逐步比较块树、UTF-16 选区、规范 Markdown、原子身份和受控保存状态；结果默认输出 `/tmp/rich-text-web-results.json`，可用 `RICH_TEXT_RESULTS_PATH` 指定位置。记录 fixture SHA-256、源码 SHA、平台、环境及首次差异字段路径；不采集真实正文。Web 没有本机关闭快照，契约 `close/local-snapshot` 标为不适用；Web 真实关闭保护由表单回归验证。阅读阶段通过实际 `MarkdownContent` 渲染 DOM 独立提取块、文字、样式与原子语义；`<br>` 后渲染器附加的格式化 LF 不重复计作软换行。编码失败没有当前 Markdown，阅读标为不适用；贴纸资产 ID 按产品规则不暴露到阅读 DOM，因此测试观察真实 ReactMarkdown 传给生产图片组件的属性，再继续调用原组件渲染并核对 DOM 图片；不从编辑模型或预期补造身份。真实 API 与负责人设备未在该执行器运行，不能据此声称已完成跨端验收。

回退只撤销相应客户端候选，不迁移或降级存量正文。未知内容可被覆盖、语义漂移或编码失败后仍提交/退出时应停止继续开放相关写能力；旧版本必须先证明可读和可保护新内容，才能作为回退版本。合并、部署与线上写入口调整另行授权。

## 文本颜色 v1

主题正文、子贴正文、楼层与回复使用独立的文本颜色 v1，不改变全局 Markdown5 或角色提及 v6。受控标记为 <code>&lt;span data-wenyou-color-v1="#RRGGBB"&gt;文字&lt;/span&gt;</code>，仅接受不透明六位 RGB，规范化为大写。Web 在正文样式菜单中提供取色，读取、编辑和站内剪贴板保留已有颜色；动态、私信、标题不开放创建。默认文字仍由主题决定，自定义 RGB 在明暗主题保持原值，颜色内的粗体、链接和代码继承该前景，背景和下划线不变。

颜色范围必须在单个物理行内、位于其他行内格式外层，不包含图片、贴纸、骰子、提及或传送门。解析只识别受控属性；不接纳任意 HTML、style 或事件属性，损坏标记沿既有安全字面降级。Milkdown 将交叉的颜色和其他格式拆为平衡范围，颜色边缘空白保留；保存前将实际文档与重新解析的彩色字符、RGB、共同格式及链接属性比较，失败则保留输入并阻止保存。源码定界符等价变化不代表格式丢失。

所有 API 请求独立声明读取颜色能力，正文写入只在 meta 支持时发送 textColorVersion=1，包括删除全部颜色。缺失支持时原稿只读保留；能力变化重新核验当前正文，草稿恢复和自动保存也受同一保护。新写开关关闭仍声明可保源，真正改字、改色、改格式或复制新范围由后端门禁拒绝，输入留在编辑器。关闭期间等价转义、定界符和紧邻同色范围的拆合可保存。

站内 clipboard v2 只保留通过校验的颜色属性；选区复制恢复颜色祖先，剪切/粘贴和单步撤销使用同一文档模型。v1 与无本站 envelope 的外部粘贴仍按既有兼容/可见文字规则，不从 CSS 猜颜色。共享语料为 [颜色 fixtures](../../contracts/markdown-text-color-v1-fixtures.json) 和 [schema](../../contracts/markdown-text-color-v1.schema.json)，受控代码、字符转义、恶意属性、边缘空白、邻接格式和关闭新写均纳入回归。实际 App 系统剪贴板保持纯文本；App 内部保色和保存后的跨端往返由对应消费者验证。

跨端编码联验使用实际 Milkdown 入口：设置 `WENYOU_TEXT_COLOR_IMPORT` 为另一端的 `{source, saved?}[]` 或 `{cases: [{source, saved?}]}` 测试内容产物，运行 `pnpm test src/components/editor/__tests__/text-color-roundtrip.test.ts`；`WENYOU_TEXT_COLOR_EXPORT` 输出本次真实解析和保存结果。产物与精确消费者 SHA、fixture SHA 分开登记，不传递未提交源码。转义的全体提及、骰子和站内地址是普通彩色字面，真实原子节点仍不能着色。

对齐与颜色的消费者回归使用生产顺序的 alignment parser/schema，再配置颜色序列化；跨端导入入口也使用该配置。永久矩阵覆盖左/中/右对齐、P/H2/H3、八种行内组合及相邻无空行边界。编辑器和阅读组件分别与独立声明的文字、RGB、全部格式及链接属性比较；见[对齐与颜色回归记录](../verification/text-color-alignment-regressions.md)。可设置 `WENYOU_TEXT_COLOR_ALIGNMENT_EXPORT` 并运行 `pnpm test src/components/editor/__tests__/text-color-alignment.test.tsx` 导出 78 个合法输入的实际保存结果，供 App 复读；产物记录 HEAD 和工作区是否干净，不能用脏树的 HEAD 冒充已提交候选。

### 正文样式菜单定位

主工具栏和“更多”中的正文样式共用锚点弹层，提供正文、标题 2、标题 3。菜单靠近触发按钮，空间不足时翻转并限制可用高度；滚动与窗口变化由共享浮层跟随。Crepe 主栏保留原触发控件和编辑器选区，不再把视口坐标写到编辑器 DOM 内的 fixed 菜单。鼠标、Enter／Space／向下键均可展开，Escape 关闭回到触发按钮；选择样式后返回正文，已有行内颜色与其他格式不变。

### Web 颜色编辑

Web 消费 [Foundation 正式 v7.6.0](https://github.com/morenk/wenyousite-foundation/blob/v7.6.0/docs/text-color.md) 的取色与光标输入规则。仅主题创建/编辑、子帖正文管理和楼层/回复共用编辑器显式开启入口；服务器必须同时声明 textColorV1Supported 与 textColorV1WriteEnabled。默认或缺失能力不开放取色，关闭新写会结束显式输入颜色，仍保留正文原有颜色与旧端覆盖保护；不会降级剥离已保存的标记。

正文样式菜单保留正文、标题 2/3，下面一行排列与移动端同源的 Foundation `editor.text-color` 默认色图标、五个固定色与自定义；最多四个最近使用的自定义色在存在时另行显示，按账号存于本机，规范化去重并以最后使用时间排序。自定义在原弹层内切换为色盘、色相条、R/G/B 和文字预览，不额外增加主工具栏按钮。通道只接受 0–255 整数；拖动和输入只更新预览，应用成功才记入最近色。取消或 Escape 不改正文，并恢复原光标/选区及输入样式。

有选区时按文本范围改色，跨段和 Ctrl+A 保留对齐、粗斜删、普通链接及行内代码，跳过图片、骰子、提及和传送门；混色不预选某个颜色，默认 T 只移除颜色。一次撤销/重做恢复整次改色。无选区时选择颜色设置待输入样式，中文、emoji、组合字符与回车续写保留显式色；主动移动光标、撤销/重做或整篇草稿替换后重新计算。范围改色不建立持续输入模式。仅光标选色、调色预览和取消均不产生正文变更，也不将草稿标记为已修改；实际输入后才保存新正文。输入法组合中不提交颜色操作。

先选色再使用输入法时，候选替换不打断组词，也不留下拼音或重复字；确认或取消候选后解除保存保护，并可重新选择已着色文字打开菜单改色。未完成组词仍阻止保存和改色。颜色输入插件在组合期间只对本次输入范围保色，结束后才恢复后续输入格式，不通过清除提交保护来接受未完成输入。

菜单使用共享锚点弹层并随全局明暗主题，键盘可遍历色块与通道；取色盘方向键调整饱和度/亮度，色相使用原生范围键盘交互。任意 RGB 保持原值，不自动调整或增加对比度提示。

### Web 编辑器高度与页脚复用

共享 `MilkdownEditor` 默认支持拖动边框调整高度，不显示拉柄图标。普通文流使用下边框向下拉高，底部浮动回复框通过 `resizeEdge="top"` 使用上边框向上拉高；边框悬停显示调整光标，聚焦后可用上下方向键沿边框方向调整。最小值沿用调用方 `minHeight`，初始自动增长上限沿用 `maxHeight`，普通文流可拖高至至少 1200px，浮动编辑器额外受视口可用高度约束，保留顶部操作空间。调节只改变当前实例正文视口，不重建编辑器、不改变正文、选区或撤销历史；重新打开恢复调用方初始高度。特殊容器可通过 `resizable={false}` 关闭调节。`footerActions` 将业务按钮插入字数右侧，默认不显示业务按钮；自动收起只由主题回复容器启用，创建页、动态与其他复用方不会因外部点击被卸载。

## 文本字体 v1

正文使用独立受控标记 `<span data-wenyou-font-v1="wenkai">文字</span>`，当前可选白名单以已提交 `thread-font-catalog-v1.json` 为准，共 28 款（中文 12、日文 10、英文 6）。退役的 `xiaocheng-lafeng` 仅保留历史解析、正文往返和显式清除，阅读与编辑使用默认字体，不请求其资源，也不从旧目录或最近记录恢复新选择。与颜色组合时同一个最外层 span 先写字体、后写颜色；内部保留粗斜删、普通链接和行内代码。禁止任意 CSS/字体名/URL、嵌套 span、空范围和跨物理行范围；图片、音频、骰子、贴纸、提及和传送门不染字体。全局 Markdown5、角色提及 v6、颜色 v1 和 clipboard v2 继续独立协商。

仅主题、子帖正文和楼层/回复的共用正文样式菜单提供字体入口。阅读与编辑分别显式开启字体作用域，共享组件默认关闭。主题列表、搜索、通知、消息、草稿摘要、身份资料弹层与管理内容预览不激活正文自选字体、不请求字库；摘要投影不改写源正文。动态及动态评论沿用纯文本/传送门能力。支持能力、独立新写开关、ready 目录及自有资源地址满足后才能新增字体；关闭新写仍可保源和清除字体。混合选区不猜测值，系统默认只移除字体 mark；跨段操作一次撤销，持续输入、IME、取消恢复、草稿替换沿用颜色的选区规则。字体与颜色相互独立，序列化校验文字及全部 marks；失去支持能力时保留未提交原文并阻止覆盖。关闭新写后改变原有字体文字/格式的限制由后端再次核验，失败不清空输入。

字体列表按正式目录的 `designLanguage` 分为中文、日文、英文；缺失或未知值保留未分类，不根据名字或汉字数量归类。列表名称始终使用系统字体，不预载字体。最近四项按账号保存并按当前白名单过滤；选择与预览不改正文，显式预览单项才请求资源；日文样文含平假名和片假名，按实际字符加载补充分片，英文样文使用拉丁文字。字体失败时预览显示系统回退。阅读、编辑与预览只对可见正文的实际码点加载固定分片；摘要不请求字体。阅读自动先用系统字体，后台校验资源或读取缓存后切换；缺字、离线及分片失败静默回退，不显示下载按钮、进度或错误提示，也不要求刷新。缺字逐字回退，不改变 fontId 或正文源。同字体后续缺字或新分片失败保留已安装家族，等待同批其他分片完成后再汇总；目录撤回、资源地址清空或 manifest 无法验证仍禁用旧家族。未知标记不激活、不作为可无损编辑内容。

资源 manifest 与分片使用 SHA-256 内容寻址；先校验 manifest、许可/归属、实际长度与完整哈希，再注册 FontFace。只接受 `wenyou.site` 及其子域的 HTTPS base，空 base 不访问字体源，不使用原始来源网站兜底。独立 `/api/v1/meta/text-fonts/runtime-policy` 返回严格 v2 策略，必须与目录及实际校验的 manifest SHA 一致；404、未知策略或错绑仍使用原 v1 限额。策略暂时不可达时保留系统字体并自动重试，不把临时故障解释成无限额度。

v2 在同一浏览器文档共享可见分片引用。离屏 200 毫秒后释放引用，前台已有选区/光标所在正文保留引用；进入后台立即释放全部需求并取消进行中传输，回前台按原账本重新请求仍可见内容，不修改选区；其他正文仍引用的分片不淘汰。空间不足时从无引用分片中按 LRU 调用 `document.fonts.delete` 并清理注册记录。活动上限为 28 家族、64 个已注册或待注册 face；普通驻留按 `max(mobile.bytes, WOFF2.totalSfntSize)` 计入 16 MiB，后者只在完整哈希验证后读取，解码前补足预留。当前可见需求自身超额时保留已就绪片并回退其余字符，待引用释放再尝试，避免互相驱逐或永久等待。完成的二进制 Promise 不保留，目录只保留当前代次；IndexedDB 为独立 64 MiB LRU。

网络使用单调时钟的 60 秒滑动窗口：64 请求、普通 16 MiB、2 并行；失败或取消已开始的请求也计入，窗口自然到期后继续排队需求。目录、策略、manifest、许可、归属和字体共用账本；无资产描述符的 API 元数据预占 64 KiB，并流式限制实际响应。离线或后台暂停新请求，前台离线仍可使用已核验本地缓存。v2 显式消费 `timeoutMode=idle-with-total-cap`：从实际请求开始到首个非空正文块、以及相邻非空块之间最多 15 秒，独立总传输上限为 600,000 毫秒；排队不计时，响应头和空块不续期。每次读取与 EOF 先核对单调截止，取消底层请求和 reader，完成后清除计时器。目录、策略、manifest、许可、归属及字体均沿用此规则；错误 HTTP 状态在响应头立即分类，不等待错误正文。网络错误、超时及 408/429/500/502/503/504 按资源连续失败计数，以 1/2/4/8/16/32/60 秒上限 full jitter 静默重试，并遵守更晚的 Retry-After；online、回前台和焦点事件不清零预算或退避。冷启动元数据全不可达也会在原页面恢复。校验、长度、MIME 和解码错误按当前资源代次隔离；目录撤回与来源清空禁用旧 face，晚到结果不能恢复旧来源。

`deliveryMode=subset` 只接受正确 MIME 的 WOFF2，单资产不超过 6 MiB。当前 v2 不含原件额外网络或驻留槽，也不接受原件例外。旧 v1 的 8 家族、64 请求、普通 16 MiB 累计限制、15 秒总超时及固定原件一次例外保持兼容，仅供旧协议读取；未清理旧 schema、历史字体 ID 或不可变资源。

字体就绪时保持可见文字滚动锚点与编辑选区；列表和摘要仍不请求字库。驻留 SFNT 输入、下载字节、JS 堆与浏览器进程 RSS 分别记录，`document.fonts.delete` 不代表浏览器立即归还原生内存；实际多轮浏览与视觉效果仍需验收。

站内 clipboard v2 只保留显式受控字体和颜色属性，恢复局部选区共同祖先；字体开启的主题编辑器粘贴时仅保留当前可选字体及支持格式；退役字体在阅读复制、编辑器内部片段及带对齐片段进入粘贴解析前移除字体属性，保留文字、颜色、粗斜删、链接与行内代码。原正文载入、编辑和草稿恢复仍按历史协议保源，复制输出不改写原文；关闭作用域的编辑器粘贴时去掉全部字体。粘贴到动态或评论时，移除字体和不支持的样式，保留文字、多段换行与合法站内传送门，普通外链保留标签文字。纯文本、外部 HTML/CSS 与未知字体载体粘贴到已有字体的插入点或范围时，仅新增文字使用默认字体，保留其他支持的插入格式、邻接文字格式和撤销能力；外部 font-family 样式不能激活字体。复制、草稿、阅读保存重开与两种样式组合使用统一解析器和真实 Milkdown 往返用例。字体资产及许可不打包进应用，完整 manifest 快照只供契约核验，不进入客户端 bundle。Foundation 继续锁定正式 v7.6.0，应用 UI 的系统字体角色不变。

## 文本字体 v2

动态字体使用 `<span data-wenyou-font-v2="tfv_0123456789abcdef0123456789abcdef">文字</span>`，ID 为不可变构建版本。字体 v2 的读取与写入声明包含 v1 能力，原有 v1 目录、资源与退役处理继续保留。合法但未知的 v2 ID 在读取、编辑、保存和草稿恢复中保源；新粘贴只接受已确认允许粘贴的版本，未知、停用或撤回时移除字体，保留颜色和其他格式。受控属性不能混用两个字体协议、不能接收任意 CSS、家族名或 URL。

颜色和字体均位于 T 正文样式菜单，与移动端保持一致，不新增主工具栏入口。独立描边的“字体”按钮在正文 / H2 / H3 左侧同一行，组间保留间隔，颜色保持原行。T → 字体直接切换到新版样张面板，不嵌套 Select 下拉。动态字体面板使用紧凑固定标题栏、标题右侧的系统默认与关闭按钮、中文/日文/英文分段筛选，以及内部滚动的真实 PNG 样张列表。每行 64px，样张优先、字体名称作为小号辅助标签；可见 PNG 解码后只收起完全透明边缘，保留全部非零 alpha 笔画和两像素余量，按比例放大到行内可用区域。像素扫描上限为 4,194,304，超过上限、全透明或读取失败时完整显示原样张；临时 canvas 在计算后释放，不生成新资源或下载字库。当前字体决定初始语言，目录延迟返回时补齐；无当前可选字体时默认中文，用户主动切换后后台刷新不重置筛选。仅存在未知语言项时显示“其他”，混合选区及历史不可选版本提供状态说明。点击字体立即应用并回到正文：无选区仅影响后续输入，有选区仅影响选中文字；取消、关闭或 Escape 恢复原选区和输入焦点。打开字体面板时释放正文输入焦点以收起软键盘；弹层随 visualViewport 尺寸及平移约束，键盘收起动画期间仍可滚动、关闭和选择。未提交的原生组合输入期间不抢焦点打开 T 菜单，也不重设输入 marks，提交完成后恢复后续字体，避免预编辑文字重复。列表支持键盘定位，保留当前项勾选和按账号记录的最近选择；打开列表和显示样张均不下载字库，可见行才请求 PNG。单色 PNG 随主题提高对比度，加载、失败和成功保持固定样张高度。目录首次加载或读取失败时仍可恢复系统默认，新的自定义字体选择保持禁用；编辑器禁用或无有效选区时仍不能应用。新版本发布不改旧帖，目录缺席仅取消选择资格，历史版粘贴、渲染权限由版本描述符决定。目录每 5 分钟、回到前台和打开选择器时复核；读取正文中的未知 ID 也会查询版本。ETag 304 保留完整缓存，分页修订冲突丢弃部分结果重读；暂时失败保留最后有效结果并尊重退避，未知 404 负缓存 30 秒。撤回立即回退默认字体、取消该版本无共享引用的资产需求，迟到结果不能恢复显示。

字体资产按浏览器解压后的实际字节核验长度与 SHA；压缩响应的 `Content-Length` 只表示传输长度，不与资产长度比较。解压后的流仍受可信描述符长度上限约束，截断、超额或哈希不符不会写入缓存或注册字体，下载进度按已接收的解压字节计量。

v1/v2 共用 60 秒 64 请求、16 MiB 和最多两个并发的网络窗口，所有目录、策略、描述符在 JSON 解码前流式限制为 64 KiB。连续传输允许最多 10 分钟，首字节和停流均为 15 秒；新目录不清零账本、注册或失败退避。运行策略只能收紧本地上限。Web 按当前驻留的 64 个 face、16 MiB SFNT 限额回收闲置注册，无固定家族数量上限；导入 v1 版本保留经验证的原 WYF1 family，相同 SHA 与 family 只占一次实际注册。二进制缓存上限 64 MiB，版本轻元数据最多 512 条、闲置最多 128 条；清单另以 128 份、16 MiB 为界回收闲置项。非作者显式选择触发的正文加载和失败保持静默，不增加下载控件或提示。

作者在当前编辑器显式应用字体后，只有该编辑作用域的实际正文需求订阅下载反馈；空光标尚无文字不发起请求或显示等待，快速就绪缓存不闪现，阅读与其他编辑器仍静默。实际需求持续 250ms 后可显示“准备字体”；策略或描述符尚未返回时不伪造总量。manifest 确认后按当前所需许可、归属及分片给出资源计划，以流式实际接收字节累计并扣除已确认缓存命中；同字体其他作用域的额外分片不计入。全部接收但尚未完成校验或注册时显示“正在应用字体”，不伪造 99% 或提前完成；就绪自动隐藏，失败显示可收起的系统回退，自动重试成功后恢复。独立进度订阅最多每 100ms 绘制，不逐块触发正文样式就绪、选区或滚动更新，不阻塞输入和 IME。共享策略请求取消不进入失败负缓存，仍存活或新到的需求可续接；真实网络错误继续遵守既有退避和预算。该反馈不变更后端契约、下载限额或选择器只加载 PNG 的规则。

已激活 v2 的浏览器文档通过固定导入映射呈现历史 v1 源码，不转换标记或跟随当前版本。停用后的历史版继续呈现但不可新粘贴，撤回立即回退默认字体；能力降级、离线、描述符 404 和迟到旧响应均不能恢复旧资源通道。所有版本（含构建后新增 ID）的撤回记录独立于两层元数据 LRU，浏览器文档内最多保存 4096 个版本 ID，且不会被旧目录或迟到描述符覆盖。记录达到上限后再收到新的撤回，当前文档静默停用全部动态字体，保留原文；这一保守回退避免遗忘撤回后重新授权，也不允许撤回记录无限增长。
