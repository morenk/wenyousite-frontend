# Markdown v5 正文内容协议

Web 与 Flutter 共用数据库中的 Markdown 字符串，不修改既有字段或数据表。

## 协议事实源

- 协议标识为 `wenyousite-markdown`，当前版本为 `5`。
- Web 仓库中的 `contracts/markdown-v4-fixtures.json`、`contracts/markdown-v4-nodes-fixtures.json`、`contracts/markdown-editor-roundtrip-v7-fixtures.json`、`contracts/markdown-v5-image-alignment-fixtures.json` 与 `contracts/editor-clipboard-v2-fixtures.json` 是后端同名黄金语料的同步副本，依次固定规范化/允许与拒绝结果、扩展节点身份、编辑器往返、图片块对齐，以及跨端复制入口、结构恢复、原子身份和可见文本回退。
- 后端是写入校验的最终权威；Web 在编辑、粘贴、恢复草稿和阅读前执行同版本降级。Flutter 必须把五份语言无关 JSON 语料纳入单元测试。
- `contracts/markdown-block-boundary-v1-fixtures.json` 补充顶层块边界、保护区、原始错误位置、编辑与复制以及空格布局回归；它是 Markdown v5 的兼容解析修正，不引入新存储格式。revision 2 同步自 Backend 提交 `a91cbb8b605223c596af299be22c5547f69e25b9`，SHA-256 为 `822509411fbf3379847a04ec64a4a32ddb1bb8fb96aecbf38b395b049134fda9`。
- [Web 实际保存验收语料](../verification/markdown-block-boundaries-web-output.json) 记录该 revision 的 173 个允许用例、4 个真实编辑操作和 1 个空白布局用例经 Milkdown 保存的实际结果，供后端独立验证消费者输出；所有内容均来自合成用例。
- 独立 Worktree 可先用 Git 从明确提交导出该 fixture，再运行 `pnpm contract:sync --block-boundary-source <文件>`，只同步该文件。完整同步、契约核对和文档事实检查统一支持 shell 环境变量 `WENYOUSITE_BACKEND_ROOT`；默认仍为相邻后端目录，显式指定的来源或契约缺失时检查失败。选择来源前须记录其 Git SHA，不能用路径选择绕过不一致。
- 规则变更必须先修改黄金语料并提升协议版本，禁止单独修改某一端正则。
- Web 的发布、回复、编辑和草稿入口传递完整规范正文，不做全局 `trim()`；`trim()` 只允许用于空内容判断，首尾空段落及空白必须保留。

## 工具栏能力白名单

只有主工具栏、“更多”面板及与这些入口一一对应的显式键盘命令可以创建结构化正文。允许普通段落、二级/三级标题、左/中/右对齐、粗体、斜体、删除线、行内代码、安全链接与自动链接、图片、引用、普通有序/无序列表、分隔线、提及、骰子、收藏表情，以及独占 `<br />` 协议空段；列表最多嵌套三层。手动键入 `## `、`> `、列表符、强调符、反引号、删除线、对齐协议或分隔线源码都只产生可见文字，不触发 Markdown input rule；标题快捷键也只保留 H2/H3。

安全链接中的合法站内坐标在编辑态显示为传送门。剪贴板纯文本整体只有一个合法站内地址时，编辑器立即创建普通链接 mark：当前选区文字作为名称，无选区时使用“传送门”。这只改变链接的编辑态呈现，持久化仍是标准 Markdown 链接，未扩展 Markdown v5 的结构能力。

表格、任务列表、围栏或缩进代码块、一级及四至六级标题、显式硬换行、任意原始 HTML、未知协议节点和超过三层的列表均不属于正文结构。Web 对粘贴、手动输入、草稿恢复与历史异常数据静默降为可见字面文本，不显示 toast 或警告；绕过客户端直接提交未转义结构时，后端返回 HTTP 400、错误码 `40009`。第三方 Markdown 解析器支持的额外语法不能扩大产品能力。

一级栏始终保持单行且不横向滚动。四档密度和每档“更多”内容直接消费 Foundation 契约：容器能放下时平铺全部常用能力，随后依次进入 `with-more`、`without-draft` 与 `compact`。标准与无草稿密度保留行内代码直达，把链接、列表和对齐收进“更多”；最窄核心栏再同时收纳行内代码与链接。“更多”是无分类、无分隔线、无常驻文字的扁平纯图标托盘，名称只在鼠标悬浮或键盘聚焦时通过 Tooltip 出现；对齐仍是段落能力，并以左、中、右三枚相邻图标组成一个复合控件。打开托盘时焦点落在托盘本身，不自动聚焦或高亮首项；工具间使用标准 `Tab / Shift+Tab`，不接管方向键或 `Home / End`。

## 顶层正文对齐

- v4 仅允许顶层非空普通段落和 H2/H3 设为左、居中或右对齐；列表、引用、普通图片、分隔线、协议空段及其他节点不参与。提及、骰子和收藏表情作为行内原子组件继承所在块的对齐。
- 左对齐是默认值且不写存储标记。居中和右对齐分别在目标块紧邻上一行写入 `[wenyousite-align-v1-center]: #` 与 `[wenyousite-align-v1-right]: #`；它们是旧 CommonMark 阅读器会隐藏的 reference definition。
- 标记必须大小写、空格、版本、枚举和邻接关系完全匹配；孤立标记、未知版本、`left` 标记、嵌套目标和不合格目标均按无效对齐处理。文字与普通图片混排仍不能独立对齐；Web 编辑器事务还会主动清除列表/引用转换后遗留的块属性。
- 受保护区外的列 0 精确标记本身建立顶层块边界，前面不要求空行，并终止列表或引用的隐式续行；标记后仍必须紧邻合格目标。校验、阅读准备、编辑回填与摘要共用块分析，错误位置保留原始零基行号；为通用阅读解析器补充的分隔只用于解析，不成为可见空段。
- 围栏、缩进代码、跨行行内代码、转义、原始 HTML 和显式嵌套中的协议字面内容不激活对齐。行内代码保护依据真实解析器消费区间，URL 和链接标题中的反引号不会误保护后续 marker。
- 阅读与编辑 DOM 只使用 `data-wenyou-align="center|right"`，不读取外部 `style`、`align` 或 CSS 推断。Web 始终兼容读取 v4/v5 正文，并只在 `/api/v1/meta.markdownContractVersion >= 4` 时显示块对齐入口、达到 v5 时开放独立普通图片块对齐；当前服务端已声明 v5。

### 普通图片块对齐扩展

`contracts/markdown-v5-image-alignment-fixtures.json` 固定普通图片块的扩展边界。服务端能力声明达到 v5 时，独立占据顶层段落的普通图片可消费同一行前置的对齐标记；无标记保持默认居左，文字与普通图片混排继续拒绝单独移动图片，收藏表情继续作为行内节点继承父段落对齐。Web 阅读器、编辑器图片块、Markdown 编解码和编辑器剪贴板均按服务端版本门控；当前服务端声明 v5，新图片对齐写入入口已开启。

## 字面文本降级

- 不支持结构按其源码行转成普通段落，并转义 CommonMark 标点；阅读和编辑界面显示原字符，序列化后仍不会重新解析为结构。
- 没有合法本站 clipboard v1/v2 标记的 Markdown、HTML、Word 和其他富文本一律优先采用剪贴板 `text/plain`；缺少纯文本时只提取 HTML 可见文字。即使内容只含白名单格式，也不得交给默认 Markdown/HTML 解析器创建结构。
- 外部拖放使用同一字面文字策略；本地文件拖放和粘贴不插入正文，图片只能经工具栏上传。
- 原始历史正文、草稿恢复和白名单外剪贴板只在进入编辑器时执行字面降级；编辑器输出端不得再次运行字面降级器。
- 客户端写出时断言序列化结果仍在白名单内；内部转换若有遗漏则停止同步且不覆盖父表单。后端始终独立校验，不信任客户端。

## 剪贴板 v2

- 阅读态同一篇 `MarkdownContent` 内的浏览器选区，以及楼层/回复菜单的“复制内容”，同时写入受限 `text/html` 站内片段和渲染后的 `text/plain`。跨正文选区不伪造结构；菜单复制整篇正文。编辑器自身的复制/剪切使用相同 v2 envelope，来源记为 `editor`。
- Envelope 写出 `data-wenyou-clipboard="2"` 和 `data-wenyou-clipboard-source="reader|editor"`，并继续读取 v1。标记只是体验信号，不是可信来源：粘贴时重新构造 H2/H3、文字 mark、列表、引用、分隔线及安全链接白名单，丢弃脚本、样式、事件属性和未知节点；未知版本静默使用系统可见文本。
- v2 只为合法顶层 P/H2/H3 保留 `data-wenyou-align="center|right"`，同块内的局部阅读选区会恢复共同块祖先；v1 一律按无对齐结构读取。外部 HTML/CSS/纯文本即使带 `text-align` 也不能创建对齐。
- 阅读态的传送门保留目标与显示名、单人提及保留 `userId` 与 label、`@全体玩家` 保留群体语义、骰子只保留表达式。粘贴骰子总是生成新 `nodeId` 且回到未结算状态；编辑器剪切后的第一次粘贴例外保留原 ID，之后再粘贴按复制处理。
- 阅读态普通图片和收藏表情分别变成 `[图片]` 与 `[表情]`，不会复制 URL 或资产 ID；编辑器内部复制继续保留可编辑媒体节点。所有 `text/plain` 回退只含渲染可见文字，不含 Markdown 定界符、目标 URL 或隐藏身份。
- 单独一个合法本站地址仍是明确例外：外部纯文本粘贴会创建传送门。混合文本、外部拖放、标记丢失、跨应用、Web↔Android 和跨设备传输均按普通可见文字处理。

## Web 编解码边界

- `milkdown-markdown-codec.ts` 是 ProseMirror 文档与持久化 Markdown 之间的唯一写出边界。所有 `docChanged` 事务完成后同步序列化一次，不依赖 Milkdown 的防抖 `markdownUpdated` 事件，也不允许骰子、表情、提及、图片等入口各自手动补发正文。
- Shift+Enter 仍保留为编辑器内 break 节点，但 stringifier 直接写成普通 LF；因此粗体末尾换行稳定输出 `**阿罗**\n下一行`，不会先生成反斜杠硬换行再被整行转义。正文重开时普通 LF 也恢复为可见 break 节点，与完整阅读态一致，不折叠成空格。
- 分隔线只写为与前后正文各隔一个空行的 `正文\n\n---\n\n正文`，并以 `horizontal-rule` 块语义验收；历史 `正文\n---` 按 CommonMark Setext H2 重开，任何编辑后统一写为 `## 正文`，不能按行级正则误判为分隔线。
- 阅读态和编辑器解析态共享同一条 attention 边界兼容：严格 CommonMark 已留在普通 text 节点中的 `* / _ / ~~` 成对定界符，只有内容首尾无空白且至少一侧为 Unicode 标点或符号时才恢复为格式；另兼容历史上恰好一个普通空格误写在定界符内、且后面紧接完整行内代码的粗体、斜体、粗斜体和删除线。恢复前用源码位置确认开闭定界符真实存在且未转义；代码、链接、图片、定义、未闭合/更长定界符和普通词内下划线不变。
- 编辑器写回时把格式节点首尾空白原样移到定界符外，不插入或折叠可见空格；stringifier 仍会把会重新造成歧义的相邻正文字符编码为数字字符引用，下划线别名统一规范为星号。GFM 删除线使用与粗体/斜体相同的相邻字符保护，规范正文重开后保持幂等。
- 骰子使用独立 Markdown AST 扩展节点和对应 stringifier handler，禁止先写成被转义的文本标记再做字符串回填。空图片清理、LF 统一、末尾格式化换行移除和独占 `<br />` 空段规范化属于无损规范化；输出阶段不得修改用户的格式语义。
- 空正文先切换为引用时，Milkdown 内部生成的引用内 `<br />` 占位会在写出边界规范化为合法的 CommonMark 空引用标记；编辑器追加的顶层空段仍沿用 `<br />` 协议。该状态不构成可发布正文，继续输入后正常写为引用正文，不得因内部占位误报原始 HTML。
- 结构块之后连续 Enter 形成的作者空段，必须保留首个 `<br />` 与结构块之间的解析分隔行；随后继续输入时不得将空段及正文吞进列表，也不得改变可见空行数量。
- 正文序列化失败时，编辑区持续显示错误，主题帖保存/发布、楼层/回复提交、子贴保存及正文草稿写入均暂停，避免将父表单中的旧内容误报为已保存。恢复为合法正文（包括撤销回原文）后重新开放；正文草稿恢复仍要求覆盖确认，不因同步失败跳过。
- Milkdown 保留结构块之后可点击的自动输入尾段，空引用沿用原有占位语义。其他自动尾段以私有 ProseMirror 属性记录来源，未使用时不进入 Markdown 或复制片段；属性不输出到 DOM、不从外部 HTML 读取。首次输入转为作者段落并纳入同一撤销历史，输入后清空以及 Enter 生成的空段按真实内容保留，撤销、重做和保存重开保持一致。跨行行内代码按 CommonMark 阅读语义将源码 LF 解释为空格，保存重开稳定，代码中的 marker 始终是字面内容。
- 站内 v1/v2 片段、单一合法站内地址、外部字面粘贴、拖放和文件忽略都在 ProseMirror DOM 事件阶段统一接管，早于默认 clipboard 解析器；只有通过严格重建的站内片段进入 Milkdown 结构解析链。所有工具栏和自定义节点事务最终都由同一个同步桥写出。

## 普通回车（候选，待负责人验收）

- 普通正文（含居中、居右）和单层引用中，一次 Enter 只新增一个可见换行；连续 Enter 保留首部、中间和尾部真正空白行，普通正文建立新排版段并恢复默认左对齐；引用不自动退出。行内粗体、斜体、删除线等遵循所属正文规则。
- H2/H3 和有序／无序列表仍由原键盘命令处理；标题末尾进入正文、列表继续下一项，空列表退出行为保持。Shift+Enter 保持已有行为。
- 新输入普通正文 Enter 用 Markdown 段落分隔保存；历史段内 LF 和 Shift+Enter 保持同段对齐。真正空白行用 `<br />`，引用内用 `> <br />`；历史引用的独占 `>` 仍是段落分隔，不等同于真正空白行。编辑器不批量改写旧帖。
- 共享事实源为后端 `3338028459561565c788d5236fb64db84a2ae538`（newline v1 revision 2）的 `contracts/markdown-editor-newline-v1-fixtures.json`。阅读与编辑按同一组可见行断言；标记只转换为安全节点，不开放其他 HTML。
- 显式空白行已占一行，阅读和编辑不再叠加其与相邻正文之间的段落间距。负责人需在更新的 Android Debug 客户端与 Web 分别验证输入、保存、重开及交叉编辑；代码测试通过不等于验收通过。

验证记录：完整 `pnpm check` 通过；候选真实浏览器已覆盖正文／引用连续回车、保存、草稿继续编辑、阅读重载与字形间距。全套浏览器中的 15 项登录旅程因部署机缺少专用 E2E 账号配置未验证；本次相关路径使用独立响应夹具完成真实 UI 操作，后端对应规范化／校验全量门禁通过。负责人仍须在专用账号执行双端实际保存复验。

## 空段落

- 编辑器将顶层空段落写成独占一行 `<br />`；`<br>`、`<br/>`、`<br >` 仅作为历史兼容输入，写入时规范化为 `<br />`。
- 白名单解析临时用独立分隔块占位，保持协议空段与相邻对齐定义的块边界和行号；普通文字占位会吞并定义而误报无效对齐。该占位不写回正文，空段仍不能携带对齐。
- 客户端渲染时把协议标记转换为安全换行节点，禁止执行任意 HTML。Web 完整阅读在解析前会隔离开头连续协议空段与正文，避免 CommonMark 将未分隔的 `<br />` 误识别为原始 HTML 块后被安全策略整体丢弃。前端摘要、通知和搜索预览会移除空段落标记并折叠连续空白。
- 完整正文阅读态把普通段落内的单个 LF 作为可见软换行保留；紧凑预览不保留该排版。
- 不设空行数量上限，仅受现有 Markdown 总长度限制；首部、中间、尾部空段落均按顺序保留。
- 对旧客户端已经写入的原始连续空行，完整阅读与编辑回填执行只读兼容推断：内部保留一个普通段落边界并把其余空行逐个恢复为空段，首部逐个恢复，尾部仅忽略一个格式化换行；围栏、缩进代码和原始 HTML 字面区域不推断。该兼容不批量改写数据库，正文下次编辑时才自然写回规范标记。

## 发布校验

纯空白、仅空段落或仅一条分隔线不可发布；图片、普通列表、普通文本、裸 HTTP(S) URL、CommonMark 自动链接和带标签链接属于有效内容。空图片/空链接以及不可见零宽字符不构成正文。草稿仍可保存为空。

收藏表情使用标准图片 Markdown `![表情](ASSET_URL "wenyousite-sticker:v1:ASSET_ID")`；Web 把它显示为最大 128px 的不可拆分内联节点，旧客户端按普通图片显示。服务端验证资产仍在作者收藏中并限制每篇 20 个。新普通图片只允许来自作者本地上传并处理完成的站内媒体；编辑历史正文时可原位保留已有外链图片，但不能新增或复制外链图片。

## 完整阅读与预览

楼层、子贴正文、楼中楼预览和独立回复使用同一渲染组件并始终完整展示，不按正文高度或视口高度折叠，也不显示“展开全文 / 收起”控件。连续空段落仍按原始数量参与排版。

搜索结果、主题卡片、用户动态和通知等不渲染完整 Markdown 的界面统一使用纯文本预览转换：HTML/数字实体按阅读语义单遍解码，换行和连续空白折叠为一个空格；骰子协议标记显示为 `[骰子表达式]`，表情显示为 `[表情]`，带标签链接显示为 `[标签]`，裸链接与自动链接显示为 `[链接]`，其他图片显示为 `[图片]`。

### 正文连续空格

完整阅读的普通段落、H2/H3、引用和列表正文保留解析后作者文字中的连续空格；编辑器采用同样的 `break-spaces` 策略。长空格可随容器宽度换行，不推断表格或竖排结构，不改变字体和 Markdown 存储格式。NBSP、全角空格、Emoji 和用于保护行首缩进的 U+2060 按原字符保留；摘要继续折叠空白。

软 LF 仍通过一个安全 `br` 节点换行。阅读器移除 Markdown 转 HTML 时生成、且没有源码位置的排版 LF，防止保留空白后把 `br` 后缀或列表块间分隔显示为额外空行；有源码位置的作者文字不参与移除。显式空段继续遵循既有协议。

历史提交 `65446d414d92e550c9ea1703c48c8250aab95eb0` 的格式节点间空格保护仍在基线中：它仅覆盖两个格式节点之间独立的纯空格文本。普通正文的空格折叠来自该保护范围不足，本次保留其回归并扩展正文块的空白样式。

- `pnpm contract:sync` 同步后端全部 Markdown fixture、站内引用、剪贴板和 OpenAPI；先校验源文件，再复制并清理仅属于 Markdown fixture 命名空间的已移除旧版本。历史 v1 副本也按事实源逐字同步，不改变其语义。
- Web 五份当前黄金语料与后端事实源逐字一致，round-trip v7、图片块对齐 revision 2 和 clipboard v2 分别符合声明的块/行内/对齐语义、复制入口、节点身份和可见文本结果
- round-trip v7 保留 30 条原语料，新增 48 条真实编辑事务：粗体、斜体、删除线、链接的 15 种组合及独立代码，在唯一可见 `anchor` 的 UTF-16 `offset` 处启用指定 marks 并输入。断言完整文字、逐段样式、规范输出、重开文档相等、幂等及删除恢复；中间位置逐条消费 `inlineInsertTexts` 的五类特殊输入。规范嵌套由外到内为粗体、斜体、链接、删除线，代码独立处理。

- 规范化、白名单判断、首个不支持类型和字面降级输出逐条符合 fixture 且幂等
- 外部粘贴、拖放、手输、撤销、草稿恢复和重开均保留可见字符，且不生成未经工具栏创建的结构；本地文件不会绕过图片上传
- 阅读选区、整篇菜单和编辑器复制都写出 clipboard v2；v1 兼容读取但不恢复对齐，v2 站内片段保存重开后保留合法顶层块对齐和白名单结构，纯文本回退不泄漏 Markdown 定界符、对齐标记或隐藏目标
- 阅读端对历史异常数据执行同一防御降级
- 所有正文提交路径保留首尾内容，工具栏插入自定义节点后立即同步外层表单；粗体后软换行不得出现裸 `**` 或尾随反斜杠

revision 2 精确示例：`[wenyousite-align-v1-center]: #\n甲\n\n乙` 显示两行，甲居中、乙左对齐；右对齐只替换标记枚举。`甲\n<br />\n乙` 才有一条真正空白行。相邻顶层正文段落不叠加 padding/margin；旧双 LF 仍保留段落结构，但同步取消额外段距。已有单 LF 不猜测按键来源，仍属于同段；自动折行不修改文档或写出换行。新行可独立设置对齐，行内 marks 保持，安全校验不放宽。HTTP/OpenAPI、Markdown v5 和 Foundation 包版本不变。

## 编辑态列表标记首行对齐

Crepe 的列表 NodeView 将标记与正文放在不同的 flex 子项中。默认标记框固定为 32px 高、24px 宽，标签另有 4px 内边距；正文则为 Noto Sans SC、17px、1.9 行高和 0.32em 段落内边距。两个框的首行位置不一致，放大正文时还会挤压两位编号。

Web 编辑态列表改为首行基线对齐，标记继承正文的字体、字号、字重和行高；无文字圆点使用展示层行框参与基线计算并居中于首行。标记尺寸以 em/lh 跟随文字，编号保持单行；不添加固定像素偏移，不改变正文段落间距、Markdown、列表树、编辑行为或发布态原生列表标记。

本次已核对远端 Foundation 正式 `v6.10.0`（`72f28500aee561cde3036a27699b5fc864bbe32d`），其字体资源和 Web Token 与本仓库锁定的 `v6.9.0` 相同。该修复只接入既有正文排版语义，不在本候选中升级无关能力。

浏览器回归使用真实 Crepe NodeView 与已加载的打包字体，覆盖中文、中英混排、两位编号、无序列表、三层嵌套、长行自动折行、亮暗主题及 100%/125%/150%/200% 正文字体缩放。编号比较同字体首字框的纵向位置（等价于基线差），圆点比较图形中心与正文首行行框中心；不插入 DOM 探针改变布局。Chromium 额外通过实际字体查询核对正文和编号均来自 Noto Sans SC；输出编辑态首屏/滚动截图、发布态截图和测量 JSON。
