# @提及编辑器模块

## 交互协议

Milkdown 编辑器在输入 `@` 时显示当前主题帖候选，候选来自后端 `/users/mention-candidates?threadId=&q=`：

- 所有角色：当前用户自己关注的人 + 帖内 `playerMarked=true` 的玩家身份用户；
- 楼主/协作者额外显示 `@全体玩家`；
- 键盘支持上下选择、Enter/Tab 确认、Escape 关闭；点击候选不会丢失光标位置。
- 候选搜索有 180ms 防抖，中文输入法组合输入期间不确认菜单；菜单会按视口自动上下翻转并限制窄视口宽度。
- 光标位于提及末尾时，Backspace 会整体删除该提及；若后面紧跟编辑器自动插入的空格，会一并删除。

单人候选在编辑器内部通过原生链接 Mark 插入，因此所见即所得地显示为 `@用户名`，不会把 Markdown 源码暴露给用户；Milkdown 序列化时才写入稳定 Markdown 链接 `[@用户名](/users/{userId})`。编辑器只把“精确 `/users/{userId}` 路径 + `@` 开头标签”标记为不可编辑原子内容，普通用户页链接及 `/users/{id}/...` 子路径不受影响。`@全体玩家`保留为纯文本保留标记。候选接口只改善输入体验，后端 `MentionsService.syncMentions()` 会在创建和编辑时重新校验并同步提及快照。

## 渲染与兼容

`MarkdownContent` 对本站 `/users/{id}` 链接使用用户提及样式并跳转到用户页；普通外链仍按安全的新窗口链接渲染。历史正文中的纯文本 `@用户名`继续正常显示，不会被错误解析成无权限用户链接。

## 验收

- 候选范围由关注关系和帖内玩家身份并集组成
- `@全体玩家`仅楼主/协作者可见且由服务端展开
- 单人提及写入稳定用户 ID 链接
- 通知与正文编辑复用同一提及快照规则
- 候选搜索防抖、中文输入法保护和窄视口菜单定位
- 用户提及整体删除

## 原子提及约束

- 精确稳定用户链接在编辑器中标记为 `contenteditable=false`
- 普通用户链接和用户子路径链接不被误标为提及
- 初次插入与编辑回填都显示 `@用户名`，Markdown 输出仍为稳定链接
