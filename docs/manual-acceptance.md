# PC Web 与站务台真人验收手册

## 1. 目标

真人验收按风险和依赖从大到小推进，不按菜单逐页浏览。目标是在 30 分钟发布冒烟中尽早发现阻断使用、权限错误、数据不一致和不可恢复操作，并在周期性深度验收中覆盖异常恢复与体验细节。

本手册只覆盖 PC Web 与站务台。自动化测试继续负责稳定、可重复的输入边界和组件行为；真人重点判断产品意图、跨页面一致性、角色边界、真实等待反馈和恢复能力。

每次执行复制[真人验收记录模板](./manual-acceptance-record.md)，不要直接在本手册中记录某次结果。

## 2. 固定准备

### 身份与窗口

使用互不共享会话的四个浏览器环境：

| 环境 | 身份 | 用途 |
|------|------|------|
| 普通窗口 A | 用户 A | 创建和管理自己的测试内容 |
| 普通窗口 B 或独立浏览器配置 | 用户 B | 检查非所有者权限和互动结果 |
| 无痕窗口 | 游客 | 检查公开可见性和匿名访问 |
| 独立站务窗口 | 管理员 | 检查站务会话、治理和恢复 |

用户登录态与站务台 HttpOnly Cookie 会话是两套边界，不在同一个窗口来回切换身份。记录账号用途即可，验收记录中不得写密码、Token、Cookie、邮箱验证码或真实会话数据。

### 工具与数据

- 记录环境、版本或提交、开始时间和执行人。
- 打开浏览器 Console 和 Network，Network 开启 Preserve log。
- 使用可识别前缀创建测试数据，例如 `【真人验收 20260814-1430】`。
- 一次验收尽量复用同一帖子和同一动态，记录其内容编号与链接。
- 写入测试只使用专用账号和测试数据；结束时恢复治理状态并清理能够安全删除的数据。
- 普通点击应立即出现禁用态、进度或结果反馈。持续 10 秒以上仍无进度说明或终态，作为 P1 候选记录；上传等长任务已经展示真实进度时除外。

## 3. 风险漏斗与停止条件

| 层级 | 先检查什么 | 通过条件 | 失败后的动作 |
|------|------------|----------|--------------|
| 1. 系统基线 | 首页、详情、站务台、API、首屏错误 | 无白屏、全局 404/5xx 或失效资源 | 停止细节检查，先确认全站还是单入口受影响 |
| 2. 身份权限 | 游客、所有者、其他用户、管理员 | 会话不串用，读写权限符合角色 | 停止内容细节，横向检查受影响角色和入口 |
| 3. 核心生命周期 | 创建、发布、读取、互动、修改 | 主流程可完成且没有重复写入或丢失 | 复现两次并记录最小阻断步骤 |
| 4. 跨入口一致性 | 首页、搜索、主页、详情、通知 | 同一状态在所有消费入口一致 | 找到最早正确和最早错误的两个入口 |
| 5. 治理闭环 | 隐藏、公开侧生效、列表、审计、恢复 | 操作有终态且可以完整回滚 | 不继续不可逆操作，保留编号和请求证据 |
| 6. 异常恢复 | 慢网、失败、重试、并发、过期会话 | 不重复写入、不丢输入、错误可恢复 | 记录触发条件及恢复后残留状态 |
| 7. 体验细节 | 布局、文案、键盘、焦点、空状态 | 不影响理解和操作 | 作为 P2/P3 集中记录，不打断主链路 |

发现 P0 或 P1 后不再向更细层消耗时间。先稳定复现两次；若重复执行可能造成资产、权限或不可逆数据影响，只复现一次并保留证据。

## 4. 每次发布后的 30 分钟冒烟

### 0–3 分钟：系统基线

1. 游客打开首页、任一公开主题帖详情和 `/search`。
2. 管理员打开 `/station` 或 `/station/dashboard`。
3. 分别刷新一次并观察 Console、失败请求和页面错误态。
4. 确认直接链接可以恢复到预期页面，而不是白屏或错误重定向。

### 3–8 分钟：游客与全局导航

1. 从首页进入分区或标签页，再进入主题帖详情和作者主页。
2. 执行一次搜索并打开搜索结果。
3. 使用浏览器后退，检查筛选、URL 和滚动位置。
4. 确认游客看不到需要用户或管理员权限的操作；访问受限入口时得到明确登录引导或正确的不存在状态。

### 8–15 分钟：用户 A 核心写入

1. 从 `/threads/create` 新建并发布一个最小主题帖。
2. 记录主题帖链接和内容编号。
3. 在详情页发布一个楼层或楼中楼回复。
4. 编辑一次自己创建的内容，核对正文和版本结果。
5. 每次提交观察按钮禁用态、反馈、请求数量和完成后的页面状态，确认没有无限转圈或重复写入。

### 15–20 分钟：用户 B 与游客交叉读取

1. 用户 B 或游客从首页、标签或分区、搜索、作者主页、直接链接中的至少三个入口找到测试主题帖。
2. 核对标题、作者、正文、回复数、时间和可见性。
3. 用户 B 尝试进入用户 A 的编辑入口或执行所有者操作，确认界面不提供越权能力，直接访问也被拒绝。
4. 若本次变更涉及通知或互动，由用户 B 产生一次互动，再由用户 A 检查通知内容和跳转目标。

### 20–27 分钟：站务治理闭环

1. 管理员从前台管理入口隐藏该测试主题帖并填写可识别理由。
2. 确认提交有明确终态，没有因目标详情变为 404 而持续转圈。
3. 游客检查直接链接以及首页、搜索、作者主页中的至少两个聚合入口，确认内容不可见且结果一致。
4. 打开 `/station/content`，在“当前隐藏内容”列表中找到该记录，核对类型、编号、隐藏理由、操作者和时间。
5. 填写复核理由并恢复；若父级仍不可见，页面应禁用恢复并解释原因。
6. 用游客重新检查直接链接及一个聚合入口，确认内容恢复公开。

### 27–30 分钟：会话与恢复

1. 刷新当前详情页并用新标签页打开其深层链接。
2. 前进、后退一次，确认 URL、筛选和滚动状态可恢复。
3. 确认用户会话和站务会话没有串用。
4. 汇总 P0/P1，记录 P2/P3，恢复治理状态并清理测试数据。

冒烟通过标准：系统基线、核心写入、跨角色读取和站务隐藏/恢复四条链路全部完成，且没有未解释的 P0/P1。跳过任何必做项时不能标记为“通过”，只能标记为“有条件通过”并写明原因。

## 5. 每周或重要版本的 2–3 小时深度验收

在 30 分钟冒烟基础上按顺序扩展：

| 顺序 | 建议时间 | 验收内容 |
|------|----------|----------|
| 全局完整性 | 10 分钟 | 首页、分区、搜索、详情、个人主页和站务台；直接链接、刷新、错误、加载与空状态 |
| 角色权限矩阵 | 20 分钟 | 游客、所有者、其他用户、管理员的读写编辑删除权限；私密、隐藏、删除和会话过期状态 |
| 主题帖生命周期 | 30 分钟 | 草稿、发布、多入口读取、回复、通知、编辑、删除或隐藏、恢复；核对计数、排序和缓存 |
| 动态与关系互动 | 20 分钟 | 图文或纯文字动态、评论、用户主页、收藏、通知；关注、拉黑和私聊边界 |
| 私密与资产功能 | 20 分钟 | 私密内容越权、重复操作、签到、打赏、钱包余额与流水一致性；只使用可控测试额度 |
| 后台治理 | 30 分钟 | 举报、案件、处置、公开侧生效、当前隐藏列表、审计、申诉或恢复；覆盖主要内容类型 |
| 异常与并发 | 20 分钟 | 慢网、请求失败、重复点击、两个标签页编辑、会话过期；检查幂等、输入保存和恢复 |
| 视觉与易用性 | 15 分钟 | 1024、1440、1920 宽度；溢出、遮挡、键盘、焦点、禁用态和错误文案 |

深度验收不追求穷举每个筛选组合。模块内部的稳定输入边界由自动化覆盖；真人应把时间放在跨模块状态、角色切换、真实反馈和可恢复性上。

## 6. 本次变更专项：一写三读一回滚

固定冒烟通过后，再围绕本次改动执行：

1. **一写**：执行一次会改变服务端状态的核心操作。
2. **三读**：从至少三个消费该状态的独立入口核对结果，优先选择详情、聚合列表、个人入口、通知或后台记录。
3. **一回滚**：执行逆操作，并重新检查一个直接入口和一个聚合入口。

选择入口时同时包含本次变更的上游入口、直接结果和至少一个下游消费者。例如隐藏帖子应覆盖：前台隐藏 → 详情／首页或搜索／作者主页 → `/station/content` 与审计 → 恢复 → 公开入口重新可见。

纯展示变更没有服务端写入时，改用“一入口、三状态”：正常、空或缺失、加载或失败，并补查一个直接链接和一个返回路径。

## 7. 问题分级与记录

| 级别 | 定义 | 示例 |
|------|------|------|
| P0 | 全站不可用、数据丢失、权限或隐私泄漏、资产错误 | 越权读取私密帖、余额错误、全站 5xx |
| P1 | 核心流程阻断或状态严重不一致 | 发布失败、无限转圈、重复提交、恢复后仍不可见 |
| P2 | 有替代路径，但次要流程或反馈明显异常 | 返回后筛选丢失、错误提示不明确 |
| P3 | 不影响任务完成的视觉或文案问题 | 间距、轻微截断、措辞问题 |

问题记录至少包含：环境与版本、角色、测试数据编号、入口、最小操作、期望、实际、复现概率、影响范围、URL、截图、失败请求和时间。相同根因影响多个页面时建立一个主问题并列出入口，不重复提交多条表象问题。

功能缺陷和产品改进建议分开记录。执行主链路时只快速记下 P2/P3，不中断当前层级；完成高风险检查后再集中补充细节。

## 8. 与自动化和发布流程的边界

- `pnpm check:full` 会在 `127.0.0.1:3101` 隔离启动本次生成的 standalone 候选构建；Playwright 不复用 `3001` 上的已部署版本，也不启动 `next dev`。写入型用例仍只连接 loopback 后端并使用可清理的专用账号。
- 发布冒烟不是 `pnpm check` 或 Playwright 的替代品；代码门禁先通过，真人再检查真实浏览器和跨角色体验。
- 除非本次改动命中相关规则，真人不穷举所有字段校验、筛选组合或像素基线。
- 公网开发环境的写入只使用专用测试账号和可识别数据，不执行批量或不可逆治理。
- 真人验收失败时保留内容编号和请求证据；确认问题前不要删除唯一复现数据。
- 验收结束后恢复所有临时隐藏或处罚，删除能够安全删除的测试内容，并在记录模板中勾选清理结果。
